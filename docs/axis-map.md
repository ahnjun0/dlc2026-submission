## 0. 먼저 — 무엇을 겨루고 있었나

```
pass@32  90.62 ~ 91.96%   ← 12개 모델 전부. 학습이 한 번도 못 움직인 축 (폭 1.34%p)
maj@32   82.17%           ← 챔피언 v2의 정직한 값 (4시드 평균, σ 0.81)
         ─────────
격차      +9.7%p ≈ 46문항  ← 남은 점수 전부가 여기 있다 (= 회수 실패)
```

**exp-045(2026-08-12)가 이 표의 마지막 칸을 채웠다**: v2가 못 푸는 3,976문항에
**가장 가까운 teacher**(Qwen3-8B, 2,864자)를 투입해 773건을 학습시켰더니
maj@32 **81.74% = clean v2 4시드 평균과 소수점까지 동일**, pass@32 **91.74%로 불변**,
**φ(v2와) 0.934 = 같은 모델 다른 시드(0.918)와 구별 불가**.
→ 단독·능력·다양성 **세 지표 모두 안 움직였다.** 학습이 아무것도 바꾸지 못한 것이다.

**핵심 사실 넷** (모든 축 판정의 배경):

| 사실 | 수치 | 함의 |
|---|---|---|
| pass@32 불변 | 11개 모델 90.65~91.96% | **학습은 능력이 아니라 회수율을 바꾼다** |
| 유효 투표수 | **n_eff = 1.5 / 32표** (φ̄ 0.60~0.66) | 32샘플이 사실상 한 접근의 복제 |
| 재정렬 표적 | 37문항(8.0%), 정답 중앙 **3표** vs 최빈오답 **10표** | 6표 차를 뒤집어야 함 |
| 정답의 순위 | 표적에서 **2위 이내가 37.6%뿐** | 상위 두 답 규칙으로는 못 닿음 |

**판정 기준** (모든 축 공통): 같은 val 460 / 같은 파서 / maj@32 · pass@32 병기 /
**최소 2시드, 기준선은 4시드 기대값** / 채택은 **문항 부트스트랩 P(이득) ≥ 95%** + pass@32 가드(하락 ≤0.5%p).

## 9. (2026-08-15 추가) **잠재 축** — 닫히지 않았고 채택도 안 된 것

### 9-1. 헤맴 점수 가중 투표 (exp-066) — **잠재 축 · fallback 보관**

샘플마다 궤적 특징 22개(길이·줄수·반복률·오류어·재확인·전환·재시작·수치재사용·

준다. 문항×모델 중심화로 난이도 교락을 제거하고, **문항 5겹 × 블록 분리**로 누설을 차단했다.

| 항목 | 값 |
|---|---|
| 블록별 Δ | +1 / +2 / +1 / +6 (s42/s142/s242/s342) |
| 평균 | **+2.50문항 = +0.54%p** |
| 문항 군집 부트스트랩 | **P(이득) = 98.9%** (게이트 95% 통과) |
| 문항내 AUC | 0.58 ~ 0.65 |
| **바뀌는 문항** | **460개 중 11개** (양 8 · 음 2) |

**왜 통과했는데 안 쓰는가 — 세 가지**

1. **유효 표본이 11문항**이다. `P≥95%` 게이트는 이런 조건을 상정하고 설계되지 않았다.
   부트스트랩이 같은 11개를 다시 뽑을 뿐이라 구간이 실질적으로 좁아지지 않는다
2. **전이율 30%** 적용 시 LB 기대 **+1.3문항** — 현 1위 마진(2문항)과 같은 크기.
   즉 *"이득의 기대값이 위험의 크기와 같다"*
3. **판정 기반이 흔들렸다** — 4블록 중 s42·s242·s342가 **같은 구형 문샷 로그**를 공유했다
   (아래 9-3). *"4블록 전부 ≥0"*의 독립성이 과대평가됐다

**되살릴 조건 (셋 다 충족돼야 한다)**

- 문샷 **8192 결정성 독립 블록 3개 이상** 확보 (현재 1개 큐)
- 재측정에서 **바뀌는 문항이 25개 이상**이고 평균 Δ가 **+3문항 이상**
- D-Day 파이프라인에 **추가 실패 지점을 만들지 않는 형태**로 구현 (사전 계산된 가중치 파일)

**같이 확정된 하위 사실 둘**

- **답 특징 7개(`a_echo`·`a_logmag`·`a_digits`·…)는 다수결의 재진술이다** —
  누설 차단 후에도 AUC는 0.85로 높은데 Δ는 −1.00. *"문항의 최빈 답에 가까운 답이 정답"*을
  학습할 뿐이라 정보량 0에 잡음만 더한다. **판별 AUC가 높은 특징이 앙상블 가중으로는 해로울 수 있다**
- **hard trim은 소프트 가중보다 약하다** — 모델별 상위 q% 제거는 q=20에서 +1.25(P=86.8%).
  헤맴이 큰 표에도 정답이 섞여 있어 **버리는 것보다 낮게 세는 게 낫다**

### 9-2. 투표 질량비 진단 — AUC를 채택 근거로 쓰지 말 것

검토자 지적으로 도입한 진단. `r_i = c_topwrong/c_gold`(필요 배율) vs
`R_i = mean(w|gold)/mean(w|topwrong)`(실제 배율).

```
구출 대상 168문항   gold-vs-topwrong AUC 0.5338
필요 배율 중앙 2.1~3.0   실제 배율 중앙 1.03   R>r 17문항(10.1%)
```

**전체 AUC 0.62는 이미 이긴 문항에서 왔다.** 접전에는 신호가 없다.

> **쌍별 우세(AUC)와 누적 질량(투표)은 다른 목적함수다.**
> 앞으로 어떤 가중·필터 카드도 **AUC가 아니라 `R` vs `r`로** 판정한다.

### 9-3. 문샷 `max_tokens` — **처음 판단은 틀렸고, 정정한 결과가 더 중요하다**

### 9-4. 체크포인트 평균은 '축소'가 아니다 (exp-067 shrink 검정)

검토자 우려: *"등간격 체크포인트에서 `Δ_t ≈ (t/T)Δ_T`이면 균등 평균은 `≈0.62×Δ_T`의 축소일 뿐"*.
LoRA **실효 델타** `(α/r)·B·A`로 직접 측정했다.

```
step    t/T    ‖Δt‖/‖ΔT‖   cos(Δt,ΔT)
  48   0.253     0.894       0.2806
  96   0.505     0.954       0.2997
 144   0.758     0.994       0.3060
 190   1.000     1.000       0.3067

λ* = 0.2835        잔차 ‖Δ_avg − λ*Δ_final‖/‖Δ_avg‖ = 0.7039
```

**전제가 기각됐다.** 노름은 `t/T`에 비례하지 않고 **스텝 48에서 이미 0.894로 포화**한다.
노름은 거의 같은데 **방향이 크게 다르다(cos ≈ 0.30)**. 따라서 평균의 **70%가 최종 방향과 직교**하며,
축소로 설명되지 않는 성분이 실재한다 → **평가할 값어치가 있다**.

부수 발견: **한 학습 런 안에서 `cos ≈ 0.30`은 놀랍도록 낮다.** LoRA 델타 방향이 크게 방황한다는
뜻이고, 전에 측정한 *"실효 이동량 0.24%"*와 정합한다.

**규정 유보**: 4.1 "가중치 병합 금지"가 같은 런의 체크포인트 평균에 걸리는지 불명 →
**서면 확인 전까지 제출 후보 제외**, 정보 목적 실험으로만 취급한다.

### 9-5. exp-035 경시 STaR — **증량 기각** (2026-08-16)

1블록 관측(A +5.75 / C −4.75)으로 4배 증량을 검토했고, **판정 규칙을 사전등록한 뒤**
2블록을 추가했다.

```

C. 중간  v2 [31,29,26,29] 28.75±2.06  vs  [24, 24]      −4.75 (−2.30 SD)
전체     maj@32 81.74% → 81.85% = +0.11%p · P(이득) 54.3%
```

**둘 다 재현 → 사전등록 규칙에 따라 증량 기각.**

**교훈 — 1블록 관측은 방향조차 못 정한다.** 어제 *"A 이득이 크고 C 손실은 잡음"*이라 봤는데

## 11. Step-DPO — 라벨러 문제를 **판정 대신 측정**으로 풀다 (2026-08-17)

### 11-1. 무엇이 막혀 있었나

Step-DPO 는 세 조각이 필요하다.

```
prompt   = 문제 + **검증된 올바른 prefix**
rejected = 최초 오류 단계
chosen   = 정답으로 가는 단계
```

**prefix 가 진짜로 올바른지가 생명이다.** 오류가 남아 있는 prefix 를 "검증됨"으로
학습시키면 모델에게 오류를 정답 문맥으로 가르치게 된다. 이 실패를 **unsafe late**
(오류 지점을 실제보다 뒤로 지목)라 부르고, 검토자 기준은 **≤5%** 였다.

### 11-2. 기각된 방식 — LLM 에게 "몇 번째 줄이 틀렸나" 묻기

`qwen3.7-plus`(사고 모드, temperature 0) 60건 판정:

```
방향 정확도        67%
**unsafe late**    **13%**      ← 합격선 5%
재실행 불안정      15%          (temperature 0 인데도 줄 번호가 바뀜)

최악 사례 train-001669 — **2번째 줄에서 이미 틀렸는데 42번째(마지막) 줄을 지목**
                        → 오류투성이 41줄이 "검증된 prefix" 가 될 뻔했다
```

**기각.** 초기 11건이 7/7 정확 방향이었던 것은 표본 운이었다.

### 11-3. 채택된 방식 — prefix 롤아웃

앞 `k` 단계만 주고 v2 가 **이어 풀게** 해서 정답 도달률 `p(k)` 를 잰다.

```
prefix 가 온전  →  이어 풀면 도달       p 높음
prefix 에 오류  →  이어 풀어도 못 도달  p 붕괴
```

**아무도 "여기가 틀렸다"고 판정하지 않는다.** 모델은 그냥 이어 풀고, 우리는 결과만 센다.
(문헌 대응: Math-Shepherd `arXiv:2312.08935` — 사람 라벨 없이 MC 롤아웃으로 단계 가치 추정)

### 11-4. 검증 — 오류를 직접 심어 ground truth 를 만들었다

`ground_truth60` 은 사람 감사라 볼 근거가 약했고(60건/10분, 생성 기록 없음),
**LLM 라벨로 LLM 방법을 검증하면 순환**이다. 그래서 정답 풀이의 어느 단계의
**계산 결과값**을 바꿔 심었다 — 그러면 오류 위치를 우리가 안다.

```
                     v1(아무 숫자)   v2(**결과값** 표적)
주입 직전 p(k₀−1)       0.867           0.896
주입점   p(k₀)          0.688           **0.421**
하락                   +0.179          **+0.475**
효과크기 d              +0.89           **+1.26**
민감도 (하락>0.10)       47%             **70%**
**조기 붕괴 τ=0.1**       3%             **0%**
온전 구간 잡음                          0.024 (p90 0.000)
```

**v1 이 약했던 것은 방법이 아니라 실험 설계 결함이었다.** 아무 숫자나 바꾸면 절반이
`160 − 60 = 20` 의 `160` 같은 **무해한 자리**에 떨어진다(뒤 단계는 `20`을 쓴다).
`= N` 형태의 **마지막 등호 우변**만 노리자 신호가 두 배가 됐다.
→ *"모델이 prefix 를 안 따른다"* 는 중간 결론은 **철회**한다.

### 11-6. 남은 리스크 (착수 시점에 미리 적는다)

1. **교환비 법칙** — 표적 개입은 비표적에서 그만큼 이상 잃었다(4회 확인:

3. **표층 통계** — `chosen` 이 체계적으로 길면 DPO 가 "길게 쓰기"를 학습한다(exp-073 교훈).

**Step-DPO 는 v2 의 시드를 다시 뽑은 것과 구분되지 않는다.**

### 11-8. 이 축이 남긴 세 가지 (결과와 무관하게 유효)

1. **검증을 포기하고 풀이로 대체하는 법** — `p(k)` 붕괴점 탐지. unsafe 13% → **0%**.
   검증자가 필요한 어떤 후속 작업에도 재사용 가능하다.
2. **`acc = 1.00` 은 손상 지표가 아니다.** d2 도 450쌍을 완전 암기했지만 `logp_c` 는 멀쩡했다.
   **진짜 지표는 `logp_c` 붕괴**이고 그것은 acc 가 1.00 에 닿은 **뒤**(epoch≈2.3) 시작된다.
3. **표 집중은 정답을 돕지 않는다.** 두 용량 모두 gold 득표를 올렸으나(P 81.5% · 90.6%)
   **우세폭은 못 올렸다**(P 52.2% · **29.4%**). 선두 오답이 gold 보다 **1.7배** 더 이득을 봤다.
   → **엔트로피를 깎는 어떤 개입도 같은 함정에 걸린다.** 앞으로 다양성 감소를 동반하는
   카드는 gold 득표가 아니라 **우세폭**으로 판정할 것.

> **다수결에서 "정답의 표를 늘리는 것"과 "정답을 이기게 하는 것"은 다른 목표다.**
> 전자만 개선하는 개입은 무해해 보이지만 실제로는 **선두 오답을 함께 키운다.**

### 11-9. 32표가 실제로 어떻게 재배치되는가 (2026-08-17)

> ⚠ **2026-08-24 정정 — 이 절의 결론은 뒤집혔다. §22 를 먼저 읽을 것.**
> 아래 `선두 오답 +0.49` 는 **선두를 사후 분포로 정의**해서 나온 값이다.
> v2 기준으로 사전 고정하면 **−0.61** 이고, 올바른 대조군(v2 자기 시드)은 **−0.95 / −1.50** 이다.
> 즉 *"오답이 세진다"* 가 아니라 *"오답을 놓지 못한다"* 이며, `gold` 상승은 전부 회귀-평균이다.
> 아래 본문은 **당시 판단의 기록으로 보존**한다 (결론 근거로 인용 금지).

총량 평균(`gold +0.122표`)은 기제를 숨긴다. **v2 의 승패로 갈라서** 보면 이렇다.

**v2 가 틀리던 84문항 — 우리가 이겨야 하는 곳**

```
            gold      선두 오답    꼬리      유효답수
d1         +0.13      +0.12      −0.25     −0.33
d2         +0.26      **+0.49**   −0.75     −0.77
```

꼬리가 버린 표의 **2/3를 선두 오답이 가져갔다.** 그리고 **용량을 올릴수록 배분이 나빠진다**:

```
gold : 오답 배분비
d1    1.08 : 1
d2    **0.53 : 1**     ← 꼬리 이동 3배 · gold 2배 · 오답 **4배**
```

exp-036 의 교환비 법칙이 **표 수준에서 재현**됐다.

**회귀-평균 반론은 성립하지 않는다.** "v2 가 틀린 문항만 골랐으니 gold 가 오를 수밖에"라는
지적은 타당하지만, 회귀-평균은 `gold ↑ · 선두 오답 ↓` 를 예측한다. 실제로는 **선두 오답이 더
올랐으므로** 선택 편향을 이기고 나온 신호이며 **보수적 추정**이다.

**승패 교체**: d2 에서 **16문항이 손바뀜**했는데 순증은 `+2`. 큰 재배치가 거의 완전히 상쇄된다.

**gold 득표 구간별** (⚠ 기준선 관측값으로 나눈 층화라 회귀-평균 혼입 · 구간당 31~42문항 ·
d1 은 16~23 구간 부호가 반대 → **채택 근거로 쓰지 말 것**)

```
 0표 (42) +0.19 · 1~7 (39) +0.46 · 8~15 (31) +0.48 · 16~23 (35) +0.60 · 24~32 (313) **−0.02**
```

중간 지대에서는 일관되게 오르나 그 지대가 **105문항뿐**이고, 24~32표는 **천장**이라 얻을 표가 없다.

> **Step-DPO 가 한 일은 "더 똑똑하게"가 아니라 "확신을 더 세게"였다.**
> 확신은 맞을 때도 틀릴 때도 세지고, **지고 있던 문항에서는 지는 쪽 확신이 더 세진다.**
> 일반화: **다양성을 줄이는 개입은 gold 득표가 아니라 `우세폭`으로 판정할 것.**

### 11-10. "중간 지대에만 d2 증원" — 라우팅 검정과 **세 번째 관문의 발견** (2026-08-17)

사용자 제안: gold 득표 중간 지대(1~23표)에서만 d2 를 쓰고 나머지는 v2+문샷 유지.

**제약**: "gold 득표 구간"은 **gold 를 알아야 정의**되므로 test 에서 관측 불가.
관측 가능한 대리 변수로 재구성 → **v2 의 1위−2위 표차**(접전도)로 라우팅.

**결과 ① 라우팅은 이득이 없다** (기준 v2+문샷 83.04)

```
τ(표차≤)   해당문항    +d2      +v2시드(대조)    차이
   0        15      83.26      83.26        +0.00
   4        72      83.91      83.26        +0.65
  12       118      83.91      83.04        +0.87
  32       460      83.91      83.04        +0.87    ← 라우팅 없음이 최선
```

**결과 ② 맞춘 대조군은 통과했으나 시드 복제에서 죽었다**

```
주 모델 시드      d2 기여      P
v2  (s42)      **+4문항**   93.4%
v2b (s142)       −2문항      9.3%
v2c (s242)       −1문항     25.1%
v2d (s342)        0문항     41.6%
평균            **+0.25문항**
```

φ 가 이유를 확정한다: **φ(v2, d2) = 0.882 = φ(v2, v2_s342)** — 소수점까지 같다.
d2 는 오류 구조상 **v2 시드 가족 안**이다 (문샷은 0.687).

**→ 판정 관문이 셋으로 늘었다**

```
① 라우터는 gold 없이 계산 가능해야 한다        (관측 가능성)
② 대조군은 **표 수를 맞춰야** 한다              (exp-055)
③ **주 모델 시드를 바꿔 복제해야 한다**          ← 오늘 신설
```

**②까지만 통과하고 ③에서 죽은 첫 사례다.** 맞춘 대조군은 필요조건이지 충분조건이 아니다.
4시드 기준선이 없었다면 `P 93.4%` 를 보고 **잘못된 카드를 채택했을 것**이다.
`exp-058_det_baseline` 의 4시드는 앞으로도 모든 풀링 판정의 필수 입력이다.

### 11-11. 가변 비중 — "v2 가 흔들리면 파트너를 더 믿기" (2026-08-17) · **폐쇄**

기존 `model_conf_pool` 은 각 모델을 **자기** 확신도로 가중(= v2 를 내리는 **교체** 방향).
이번 것은 v2 의 접전도로 **파트너를 올리는(증원)** 방향이라 별개 카드다
(실측: 증원 +1.07 vs 교체 −1.7 이므로 방향 구분은 실질적).

    score(a) = n_v2(a) + w(q)·n_partner(a),   w(q) = 1 + α(1 − m/32),  m = v2 top1−top2

**결과 — 문샷(현행 파트너)에서 단조 악화** (4시드 평균)

```
α        0      0.5      1.0      2.0      3.0
조건화  83.26   82.77    82.72    81.90    **81.25**
균일대조 83.26   83.04    83.04    82.45    82.07     ← **조건화가 균일보다도 나쁘다**
```

**기제 — 파트너의 조건부 신뢰도를 직접 재서 확정**

```
v2 표차      문항    v2      문샷      판단
0~2          50    12.0%   14.0%   파트너가 근소 우위 — 단 **둘 다 못 푼다**
3~8          46    39.1%   34.8%   파트너가 나쁘다
9~20         53    84.9%   **62.3%**  파트너가 **22.6%p** 나쁘다
21~32       311    98.7%   97.4%
```

두 겹으로 실패한다.
**① 접전은 "누가 아느냐"가 아니라 "아무도 모른다"는 신호다.** 최접전 50문항은 12%↔14%다.
**② 연속 가중이 파트너가 훨씬 나쁜 구간으로 샌다.** 표차 15 에서도 `w=1+0.53α` 라,
**22.6%p 나쁜 모델에 53문항에서 1.5배 가중**을 준다. 최접전에서 얻는 미미한 이득을 압도한다.

> **일반화: 가중의 조건 변수는 "주 모델의 불확실성"이 아니라 "그 구간에서 파트너가 더 정확한가"
> 여야 한다.** 전자는 난이도 대리변수일 뿐이고, 난이도가 높으면 **파트너도 같이 못 푼다.**
> 조건부 신뢰도표(위)를 먼저 그리지 않고 가중 카드를 설계하지 말 것.

**현행 균등 32+32 = 83.26%(4시드 평균)가 모든 α 를 이긴다. D-Day 구성 변경 없음.**

**(기록 누락 교정)** `src/eval/model_conf_pool.py` 의 결과가 문서에 남아 있지 않았다.
스크립트만 있고 판정이 없는 축은 **없었던 실험**이다 — 이번에 증원 방향으로 다시 재서 채웠다.

### 11-12. d4 의 오답을 **직접 읽었다** — 엔트로피 붕괴의 실제 얼굴 (2026-08-17)

d4 가 C·D 구역에서 잃은 **17문항** 중 3건을 원문으로 읽었다.

**① `train-003430` — 순수 덧셈 실수** (v2 32/32 정답 → d4 32/32 오답)

```
v2:  10 + 5 + 7 + 6 = **28**
d4:  10 + 5 + 7 + 6 = **38**
```

추론 구조가 **문장 단위로 거의 동일**하다. 분해·순서·표현이 같고 틀린 건 덧셈 하나다.

**② `train-004997` — 또 덧셈 실수** (설정은 완벽)

코사인법칙을 정확히 세우고 `cos120° = −1/2` 도 맞게 처리한 뒤
`c² = 9 + 25 + 15` 까지 정확하게 쓰고 **`c² = 59`** 라고 적었다 (49 다).

**두 사례의 오차가 둘 다 정확히 `+10`**(28→38, 49→59)이다. 표본 2 라 단정 불가하나
자릿수 처리 손상을 시사한다.

**③ `train-000188` — 정의 붕괴** (성격이 다른 유일한 건)

```
v2:  "진부분집합은 자기 자신 제외" → 8개 나열 → **8 − 1 = 7**
d4:  "진부분집합의 개수는 2ⁿ"      → 8개 나열 → **8**
```

d4 는 정의를 틀리게 진술한 뒤 8개를 성실히 나열하고 *"확인해 보니 8개"* 라며
**오답을 자기 검증으로 강화**한다.

**→ `pass@32` 는 그대로인데 `maj@32` 가 무너진 이유**

> **다수결이 작동하는 이유는 계산 실수가 무작위이기 때문이다.**
> 32번 뽑으면 실수 지점이 매번 달라 정답이 최빈이 된다.
> **d4 는 실수를 결정론적으로 만들어 다수결의 작동 원리 자체를 제거했다.**

`10+5+7+6` 을 32번 물어 32번 다 `38` 이면 표를 늘려도 못 건진다.
우리의 오래된 진단 — *"모델은 방법을 알지만 다단계 계산에서 붕괴한다"* — 과 맞물린다.
**d4 는 능력을 깎지 않고 그 붕괴를 재현 가능하게 만들었다.**

17건의 편차는 대부분 **작은 체계적 오프셋**이다 (`±1` 다수 · `−10` · `×2` · `×5` ·
중앙값 위치 오류) — 오답 분석의 *"체계적 오답 59%"* 분포와 같은 얼굴이다.

**일반 규칙**: 다양성을 줄이는 개입은 **오답의 종류를 바꾸지 않고 오답을 고착시킨다.**
따라서 그런 카드는 `pass@32` 로 안전을 확인해도 소용없다 — **`maj@32` 와 다양성을 함께 볼 것.**

### 11-13. 선행연구 대조 — **우리 실패는 예측 가능했다** (2026-08-17)

**① `logp_chosen` 하락 = likelihood displacement (기지 현상)**

- `arXiv:2410.08847` **Unintentional Unalignment: Likelihood Displacement in DPO** (Razin 외)
  DPO 중 **선호 응답의 확률이 오히려 감소**. 원인은 **chosen·rejected 의 임베딩이 유사할 때**.
  `CHES` 점수로 그런 표본을 걸러내면 완화.
- `arXiv:2402.13228` **Smaug: DPO-Positive** (Pal 외)
  상대 확률은 오르는데 절대 확률이 떨어지는 실패를 이론·실증으로 규명.
  **"쌍 사이의 편집 거리가 작은 데이터셋에서 특히 심하다."**

> **Step-DPO 의 쌍 구성은 이 실패 모드의 교과서적 최악 조건이다.**
> 우리 쌍은 **같은 문제 · 같은 prefix** 를 공유하고 **단계 하나만** 다르다 —
> 편집 거리 최소, 임베딩 유사도 최대. 두 논문이 독립적으로 지목한 바로 그 지점이다.

**→ 우리 실패는 라벨 품질도 데이터 양도 아니었다.** prefix 롤아웃 라벨러는 정상 작동했고
(unsafe 0%) 쌍도 제대로 만들어졌다. **Step-DPO 의 쌍 구조 × 표준 DPO 손실**의 구조적 충돌이다.

**② 다양성 붕괴 (기지)** — `arXiv:2310.06452` (Kirk 외): "RLHF 는 SFT 대비 출력 다양성을
유의하게 감소시킨다". 일반화↔다양성 트레이드오프.

**③ 첨예화가 큰 k 를 해친다 (기지)** — `arXiv:2504.13837`: RLVR 은 작은 k 에서 우세하나
**k 가 크면 베이스의 pass@k 가 더 높다**. RL 은 새 추론을 만들지 않고 기존 것을 집중시킨다.

**우리 결과의 새로운 부분**

```
d4:  pass@32  91.09% (기준선 +0.22)   ← 커버리지 유지
     maj@32   79.35% (−2.39%p)        ← 집계만 붕괴
```

선행연구는 "다양성이 준다" · "pass@k 가 준다"까지 말한다. 우리는 **`pass@k` 가 유지된 채
`maj@k` 만 무너진 사례**를 잡았고, 원문 판독이 이유를 보여준다 —
**다수결은 실수가 무작위라서 작동하는데 엔트로피 붕괴가 실수를 결정론적으로 만든다.**
**커버리지 손실과 집계 실패를 분리한 관측**이며 위 세 논문 어느 것도 이 형태로는 말하지 않는다.

**되살릴 경로 (지금은 아님)**: `DPO-Positive`(chosen 절대확률 하락에 페널티) + `CHES` 필터링이
우리 쌍의 병리를 직접 겨냥한다. 단 **d2 는 `logp_chosen` 손상이 −3.4 nats 로 미미했는데도
단독 무효**였으므로 변위를 고쳐도 이득 보장은 없다.

**⚠ 확인 실패**: "산술 회로가 초기 레이어에 있다"는 문헌 근거는 확보하지 못했다
(`arXiv:2410.21272` 초록으로는 국소화 위치 확인 불가). **11-14 의 초기 레이어 편중 관측은
우리 실측일 뿐 문헌 뒷받침이 없다** — 산술 프로브(exp-080)로 판단할 것.

### 11-14. LoRA 가 **어디를** 바꿨나 — 산술 손상의 위치 (2026-08-17)

```
전체 평균 상대 변화량 ‖ΔW‖/‖W‖
v2(SFT) **0.253%**  ← 산술 멀쩡      d1 0.058%   d2 0.089%   d4 **0.154%** ← 산술 손상
```

**"많이 덮어써서"는 기각** — v2 가 1.6배 더 움직였는데 멀쩡하다.
**"특정 모듈을 덮어써서"도 기각** — 모듈 분포 모양이 v2 와 사실상 동일(gate/up 최대, down 최소).

**레이어 깊이에서만 실제 차이가 난다** (초기/중기 비):

```
v2(SFT) 1.15   ·   d1 1.34   ·   d2 1.45   ·   d4 1.41
```

**DPO 는 용량과 무관하게 초기 레이어에 변화를 몰아넣고 SFT 는 그러지 않는다.**
초기 레이어는 토큰 수준 표현(숫자 토큰·자릿값)이 형성되는 곳이나, **이는 상관이지 인과가 아니며
문헌 뒷받침도 없다**(11-13 참조). exp-080 산술 프로브가 인과를 가른다.

### 11-15. 산술 프로브(exp-080) — **"DPO 가 계산을 망가뜨렸다"는 기각** (2026-08-17)

400문항 순수 계산(추론 난이도 0) · greedy · 5모델.

```
모델      전체    sum4   carry3   big2    mix     mul
base     96.5    99.2    93.8    93.8   96.7    98.3
v2       97.0   100.0    96.2    92.5   96.7    98.3
d1       95.8   100.0    93.8    91.2   93.3    98.3
d2       96.0   100.0    92.5    95.0   93.3    96.7
**d4     98.0**  99.2   **98.8** **97.5** 95.0   98.3   ← 5모델 중 1위
```

**d4 가 순수 계산에서 가장 정확하다.** 자리올림 98.8 · 3자리 97.5 로 v2 를 넘는다.
`10+5+7+6=38` 은 **덧셈을 못 해서가 아니다** — 직접 물으면 정확히 더한다.

**→ §11-14 의 "초기 레이어 편중 → 산술 손상" 해석은 철회한다.**
초기 레이어 편중(DPO 1.4 vs SFT 1.15)은 실측 사실이나 **산술 손상의 원인이 아니다.**
(문헌 뒷받침도 없었다 — §11-13 참조)

**남는 기제는 하나뿐이다**

> **모델은 더할 줄 안다. 다만 긴 추론 안에서 한 번 미끄러지고,
> 엔트로피가 붕괴돼 32번 다 같은 길로 미끄러진다.**

능력이 아니라 **경로 다양성**의 문제이며 `pass@32` 불변과 정확히 일치한다.
d4 는 **단발 계산을 더 잘하게 만들면서 동시에 실수를 재현 가능하게** 만들어
순증 −2.39%p 를 냈다. `arXiv:2504.13837`(RL 은 작은 k 를 올리고 큰 k 를 내린다)의
우리 버전이며, 우리는 그것을 **`pass@k` 가 아니라 `maj@k` 에서** 관측했다.

### 11-16. d2 를 주 모델로 쓰는 구성 — **4시드 기각** (2026-08-17)

### 11-17. CHES 실측 — **DPO 계열 4연속 실패가 하나로 설명된다** (2026-08-17)

`arXiv:2410.08847` 의 CHES 를 우리 선호 쌍에 직접 계산했다 (v2_merged 마지막 층 히든 상태를
응답 토큰에 대해 합산 → 데이터셋 평균으로 중심화 → 코사인. 논문의 근사 구현).

```
                  CHES 평균   중앙값    p10      표준편차   셔플 대조
Step-DPO(079)    **0.9760**  0.9857  **0.9463**  **0.0304**   0.0069
±1 DPO(073)        0.8519    0.8989    0.6915      0.1658    −0.0209
DPO1(032)          0.8800    0.9250    0.7155      0.1330     0.0419
```

셔플 대조군(i 의 chosen × j 의 rejected)은 **0.007 로 사실상 직교**한다.

**① CHES 필터는 우리 데이터에 쓸 수 없다 (실측 확정)**

`p10 = 0.9463` — **가장 안 닮은 하위 10% 조차 0.95 위**다. 표준편차는 0.0304 로 다른
데이터셋의 **1/5**. **걸러낼 "나쁜 꼬리"가 따로 없고 분포 전체가 나쁜 꼬리다.**
의미 있는 수준(<0.90)까지 자르면 450쌍이 거의 전부 사라진다.

**② DPO 계열 4개 실험이 하나의 구조적 원인으로 설명된다**

```
exp-032 DPO1      CHES 0.880   → 폐쇄
exp-036 DPO2      (동일 구조)   → 폐쇄
exp-073 ±1 DPO    CHES 0.852   → 폐쇄
exp-079 Step-DPO  CHES **0.976** → 폐쇄   ← 가장 극단, 가장 크게 붕괴(d4 −2.39%p)
```

전부 **"같은 문제에서 만든 쌍"**이다. 같은 문제의 두 풀이는 프롬프트·주제·표현을 공유하므로
**구조적으로 CHES 가 높고**, CHES 가 높을수록 DPO 는 선호 응답의 확률을 떨어뜨린다.
**CHES 순서가 곧 극단성 순서**라는 점도 맞아떨어진다.

> **우리 DPO 계열의 4연속 실패는 개별 설계 결함이 아니라 하나의 구조적 원인이었다.**
> 수학 문제의 선호 쌍은 **정의상 같은 문제에서 나와야** 하므로 이 함정은 회피할 수 없고,
> **손실 함수 수정(DPOP)으로만** 넘을 수 있다. 그 기대 이득은 용량-반응 기울기상
> 시드 잡음(5문항) 이하이므로 **D-14 시점에 착수하지 않는다.**

**도구**: `src/eval/ches_score.py` (셔플 대조군 내장 — "높다"를 말하려면 기준선이 있어야 한다)

## 13. 선택기 두 카드 추가 폐쇄 — **수확 축도 닫혔다** (2026-08-17)

접전 문항(표차≤8)에서 top-2 를 가리는 중재자를 두 방식으로 시험했다.
사전 등록 문턱은 **판별 AUC ≥ 0.65** — 다수결이 그 구간에서 25~26/85~88 을 맞히므로
그 미만이면 **중재가 오히려 손해**라는 산수에서 나온 값이다.

### 13-1. 역방향 검증 (exp-083 · `arXiv:2212.09561`)

답을 조건으로 주고 **원 문제의 가린 수치를 되찾게** 한다. 68문항 × 2후보 × n=8.

```
**AUC 0.516**   기권 **37/68 (54%)** — 두 후보 모두 X 를 못 되찾음
구역별  A **0.500**(정확히 동전) · C 0.417 · D 0.567
```

**실패 원인은 3B 의 판정력이 아니라 역문제의 ill-posedness 다.**
프롬프트를 읽어 **생성 전에** 예측했다: *"X자리 문자열의 첫 자리가 2다"* 에서 답(4)을 알아도
X 가 3003 인지 5 인지 알 수 없다. **A구역(조합·존재)은 원리적으로 역산 불가**이고
접전의 41%(36/88)가 거기 있다 — **적용 가능성이 우리 필요와 반대로 상관**돼 있다.

### 13-2. prefix 롤아웃 선택기 (exp-084 · 우리 아이디어)

후보 X 를 낸 풀이의 prefix 들에서 이어 풀어 **X 재도달률 R(X)** 를 잰다.
역산이 필요 없어 **적용이 넓다**(85/88, 기권 9%). 85문항 × 2후보 × 4지점 × n=4.

```
**AUC 0.553**   gold 쪽 R 0.678  vs  오답 쪽 R 0.621   ← 방향은 맞으나 약함
구역별  A 0.577 · **D 0.639**(가장 근접) · C **0.286**(역방향)
**실제 중재:  25/85 → 21/85  (−4문항)**   ← 문턱 산수가 실증됐다
```

### 13-3. 종합 — 선택기 **5회 독립 폐쇄**

```
exp-008 즉답식 ORM      52.6%   판정형
exp-015 GenSelect       50.0%   판정형
exp-038 국소 단계 PRM    45.9%   판정형
exp-083 역방향 검증   AUC 0.516  측정형 — 측정이 ill-posed
exp-084 prefix 재도달  AUC 0.553  측정형 — 측정은 되나 신호가 약함
```

> **"판정 대신 측정"은 라벨링에서는 통했지만(unsafe 13%→0%) 선택에서는 통하지 않았다.**
> 두 측정 기반 선택기가 모두 동전 근처다. 즉 **필요조건이지 충분조건이 아니다** —
> 측정이 가능해도 그 측정이 **정보를 담아야** 한다.

**결론**: 접전 문항에서는 **모델 자신으로부터 계산 가능한 어떤 신호도 정답과 선두 오답을
가르지 못한다.** IRT 의 "남은 0.4%p" 와 `12%p` 수확 격차가 닿지 않는 이유가 이것이다.

**성능 축·수확 축 모두 닫혔다. D-Day 구성 불변.**

### 15-6. **"±0 자체가 손해 아닌가"** — 반사실 검정 (2026-08-21)

사용자 반박: *"무학습 = v2 라는 것은 오염이 이득을 먹었다는 뜻일 수 있다."*
**논리는 타당하다.** `±0` 은 `손해 없음` 을 증명하지 않는다.

**그리고 v5a 는 이 반사실을 검정하지 못했다**:

```

v5a 잔존 오염   357개 (2.35%)   ← **81% 가 양쪽에 그대로 남음**
→ v5a 가 없앤 것은 **탐지 가능한 19%** 뿐. 사각지대는 v5a 에도 그대로였다
```

**그러나 오염도가 다른 모델들을 비교하면 관계가 없다**

```
모델                    train 라벨 오염        maj@32   pass@32
무학습 baseline          0% (학습 안 함)         81.74    91.30
**문샷 (100% 외부 R1)**   **0%** (train gold 미사용) 78.04  **90.65**  ← 최하

**cleanv2 (동일 데이터)** **2.90%** (v2 와 동일)  81.52  **91.74**  ← 최상
extstar (외부 문제)       외부 gold             82.61    91.52

```

**두 가지가 가설을 무너뜨린다**

2. **오염 0% 인 문샷이 `pass@32` 최하위(90.65)다.** 외부 R1 만 썼고 train gold 를
   한 번도 안 봤다. 오염이 원인이면 최상위여야 한다.

**정직한 상한**: 오염에 비용이 있다면 **같은 데이터 잡음(0.87%p)보다 작다** —
우리가 애초에 구별 못 하는 크기다.

       exp-024(외부 +2.5만 문항)가 −0.22%p 였으므로 데이터 양 축은 이미 무효
```


### 15-7. 라벨 정화 재학습 — **실측 완료 · 챔피언과 동률** (2026-08-21)

§15-6 에서 *"진짜로 깨끗한 모델을 학습한 적이 없다"* 를 미검정으로 남겼다. **닫았다.**

```
              v2      aol(마스킹)   clean+aol(마스킹+정화)
평균        81.63       81.20            **81.63**
pass@32     91.20       91.74             91.41
다양성       5.17        5.08              5.00

clean+aol vs v2 :  순 **+0.0문항** · P **47.3%**  ← 완전 동률 (2시드 모두 소수점까지 일치)
```

**오염 6.23%(1,196샘플)를 전부 제거해도 순이득이 0이다.** 정화 이득(+2문항)과
데이터 축소 손해가 상쇄된다 — `pass@32` 가 91.74 → 91.41 로 내려간 것이 축소의 대가다.

**→ §15-6 의 반사실이 닫혔다.** *"±0 은 오염 때문 아닌가"* 에 대한 답은 **아니다**이다.


### 15-8. 2×2 완성 — 라벨 정화의 **진짜 주효과는 +0.11%p** (2026-08-22)

§15-7 에서 `clean+aol` 이 챔피언과 동률이었고, 정화의 순효과는 `+2문항`(P 74.9%)이었다.
그 `+2` 가 **마스킹 유무와 무관하게 가산적인가**를 검정하러 네 번째 칸을 채웠다.

```
2시드 평균            마스킹 X    마스킹 O
오염 데이터            81.63      81.20
정화 데이터            81.41      81.63

**주효과: 라벨정화 +0.11%p · 마스킹 −0.11%p**  (v2 시드 폭 1.09%p 의 1/10)
```

**가산성은 성립하지 않는다.** `clean+ctrl`(정화+챔피언 레시피)은 v2 대비 **−1문항**이다.
`exp-087` 의 +2문항은 **마스킹이 만든 손해를 되돌린 것**이지 정화의 순이득이 아니었다.

> **"정화가 효과 있으면 최대한 쓰자"에 대한 답: 쓸 만한 효과가 아니다.**
> 외부 제보 1,065건을 전부 반영해도 주효과가 0.11%p 이고 배포 구성은 오히려 −1문항이다.

**부수 실측**: 마스킹은 `grad_norm` 을 **51%**, `entropy` 를 **27%** 낮춘다.
프롬프트 토큰이 토큰 수로는 21.3% 지만 손실·그래디언트에서는 훨씬 큰 몫이었다.

## §16 — 라벨 정화 축 (2026-08-22) · **㊳ 폐쇄**

외부 제보 1,065건 + 우리 1,182건으로 `sft_v2` 의 오염 **1,196샘플(6.23%)** 을 제거해 재학습한
`clean+ctrl` 을 **단독·앙상블·LB** 세 층위에서 검정했다.

| 층위 | 결과 |

1. **게이트(P≥95%)의 판별력이 두 번째로 실증됐다.** 90.2% 로 미달이라 유보했던 카드가
   LB 에서 실제로 졌다. `sub-005`(70.8% → −4문항)에 이어 두 번째 역예측 성공이다.
2. **짝 대조군은 같은 생성 배치로 만들어야 한다.** `sub-008`(0.80385)은 3자 구성인 데다
   생성물이 소실돼 짝이 안 맞는다. 같은 배치의 `sub-010`(0.80024)과 비교해야 −2문항이 보인다.
   **후보만 냈다면 −5문항으로 과대평가**했을 것이다.
3. **공통 성분은 복제하지 않아도 된다.** `문샷+X` 에서 X 만 바꾸므로 문샷은 짝 차분에서
   상쇄된다. 문샷을 s42 로 고정하니 4시드 판정이 **50분**에 끝났다(시드당 3.5시간 절약).
4. **스크립트에 호스트를 박아두지 말 것.** `backup_to_hf.sh` 에 반납된 서버 주소가 남아

## §17 — 갈림길 다양화 · 담화 표지 (2026-08-22) · **㊴ 폐쇄**

### 17-1. 착수 전 자체 반증 (exp-091)

가설: *"32샘플이 같은 길로 가서 뭉친다 → 갈림길에서만 온도를 올려 흩는다."*
사용자가 **"N=48·T=1.3 의 근거가 있느냐"** 고 물어 실측했더니 **전제가 틀렸다.**

| 측정 | 값 |
| --- | --- |
| 갈림길 위치 (정답 vs 최빈오답 공통 접두) | **p50 7토큰** · p75 21 · p90 34 → N=48 은 이미 지나친 자리 |
| 현행 T0.8 접두 고유 개수 | N=16 → 10/32 · N=48 → **28/32** · N=64 → 31/32 |
| **접두 다양성 ↔ 답 다양성 상관** | **r = 0.105** |
| 같은 접두인데 답이 갈리는 문항 | **61/78** → 분기는 접두 **이후** |

**28가지로 다르게 시작해 15가지 답으로 수렴한다.** 표면 경로를 흩어도 결론이 같다 —
샘플링 문제가 아니라 **믿음**이다.

**의미 수준 재확인** (사용자 지적: *"표면만 다른 것 아니냐"*):

```
접두 어휘 Jaccard   v2 내부 **0.545**  vs  문샷 0.289  vs  무관 문항 0.156
수치군으로 군집       표면 28가지 → **수치군 5가지** (압축 5.6:1)
```

의미 수준에서는 좁은 것이 맞아 한때 실험을 되살렸으나, 온도 스윕(N∈{12,24}×T∈{0.8,1.2,1.6})
결과 **새 수치의 71.6%가 본문에 없는 서식 잡음**(`'1'` `'2'` `'03'` 등 단계 번호)이었고,
접두를 직접 읽으니 T=1.6 도 **같은 일**을 하고 있었다.

### 17-2. 담화 표지 — 방향이 반대였다

동료 조언: *"however 같은 토큰 좌우로 뉘앙스가 바뀌니 그 부분을 주목하라."*

| 층위 | 결과 |
| --- | --- |
| **위치 가설** (분기점 국소화) | **기각** — 분기점 ±60자 표지 밀도 **0.00**/1000자 vs 그 외 0.25. **농축비 0.00배** |
| **품질 신호** (표지=나쁨) | **확인** — 문항 내 **−13.8%p**, P=100%. 문샷은 표지 보유율 99.9%라 변별 불가 |
| **쓸 수 있는 곳** | 전체 AUC 0.552 → **접전(표차≤4) 0.529 [0.496, 0.559] = 무정보** |

표지는 *"전환이 일어나는 자리"* 가 아니라 **이미 갈린 뒤 헤매는 자리**다. 분기점은 **25자(1.2%)**
지점인데 표지는 훨씬 뒤에 나온다. 그리고 `exp-066` 이 이미 **특징 22개**로 상위호환을 만들어
게이트를 통과(P 98.9%)하고도 **바뀌는 문항 11개**라 미채택했다.

### 17-3. 진단 정정 — "뭉침" 은 오답의 절반 이하다

```
틀린 78문항 전체   최빈 득표 중앙 **9/32** · 고유 답 **15가지**
뭉친 지대(확신오답 25 + 경계±1 9) = **34/78 (44%)**
나머지 56% 는 **이미 최대로 흩어진 채 틀린다**
```

**표적이 둘로 갈린다** — 앞단은 좁고(다양화 필요), 뒷단은 흩어져 있다(안정화 필요).
같은 개입으로 둘 다 잡을 수 없다. 그리고 이 정정이 **로짓 증류의 기제 근거를 약화**시킨다:
"뭉침을 흩어 회수" 가 아니라 **"믿음을 바꾼다" = pass@32 채널**만 남고,
그 채널은 **"능력↑ 점수↔" 이 다섯 번 재현된 자리**다.

### 17-4. 방법론 신설

> **하이퍼파라미터의 근거를 데이터로 못 대면 그 실험은 아직 설계되지 않은 것이다.**
> `N`·`T` 를 어림으로 정했고, 근거를 요구받아 재보니 **가설 자체가 무너졌다.**
> 사전에 "이 값이 왜 이 값인가" 를 답할 수 없으면 착수하지 않는다.

> **프록시 정제를 멈출 지점을 정해둘 것.** 수치군 지표가 세 번 침식되는 동안
> 실측 비용은 25분이었다. **프록시 개선 비용 > 실측 비용이면 즉시 실측으로 간다.**


## §18 — **몰아주기 실패**: 여섯 번 반복된 단일 패턴 (2026-08-23)

이 문서의 폐쇄 축 대부분이 **같은 한 가지 이유로** 죽었다는 것이 오늘 확인됐다.

| 실험 | pass@32 | maj@32 |
| --- | --- | --- |
| `exp-081` DPO β앵커 | **92.61%** (최고) | **+1문항** · 신규 커버 11문항 gold 중앙 **1표/32** · 다수결 승리 **0** |
| `exp-094` prefix | **92.17%** (2위) | −0.22%p |
| `exp-086` aol | 91.74% | −2문항 |
| `exp-088` clean+ctrl | 91.52% | −1문항 |
| `exp-092` KD(결함판) | 88.70% | −5.65%p |
| `exp-055` 층 증설 | 91.74% | ±0.00 |

**`exp-055` 가 기제를 직접 측정했다**:

```
Δgold **+0.14**  ·  Δ최빈오답 **+0.08**  →  **Δmargin +0.07**
```

> **개입이 gold 를 특정해 밀어주는 게 아니라 분포 전체를 들어올린다.**
> 그래서 능력은 오르고 순위는 안 바뀐다.

**따라서 앞으로 모든 판정의 주 지표는 `Δmargin` 이다.** `Δgold` 만 보면 착시가 생긴다.
설계 대응은 `docs/majority-aware-rl.md`.


## §19 — **어휘 전수 스윕**: 오답 편중 단어는 있으나 확신이 아니다 (2026-08-23)

§17 에서 담화 표지(however/wait)를 닫았지만 그건 **손으로 고른 표지**의 검정이었다.
여기서는 **어휘 1,272개 전체**를 훑었다 (val460 · 샘플 29,440 · **문항 단위 5-폴드 교차적합**).

### 찾긴 찾았다 — 그런데 주제어다

```
오답 편중  combinatorial 15.2% · subsets 16.2 · lie 16.9 · arrangement 18.4
           inclusion 18.2 · edges 19.3 · positions 20.6 · **messy 19.3**
정답 편중  boxed 76.9 · cookies 97.2 · **confident 96.5** · john 96.2 · packs 96.3
```

`cookies·john·packs` = **orca_math 서술형**(최고 91.5%) · `combinatorial·subsets` = **조합론**(최악 36.4%).
→ *"이 문제가 어려운가"* 를 맞히는 것이지 *"이 풀이가 맞는가"* 를 맞히는 게 아니다.

### 문항 간 / 문항 내 분해 — **이 분해가 핵심이다**

```
**문항 간** AUC        0.790    ← 어려운 문항 탐지. **투표에 무용**
**문항 내** 전체        0.687    ← 실재 신호. 손으로 고른 exp-066 22특징(0.62)보다 낫다
**문항 내** 결정 지대   **0.575**   ← 필요치 0.70 미달
담화 표지 10개만        0.626 / **0.565**
```

> **한 문항의 샘플들이 같은 점수를 받으면 다수결은 한 표도 안 바뀐다.**
> 투표 가중 판정은 **반드시 문항 내 AUC 로** 해야 한다. 문항 간 AUC 는 착시다.

### 실측 적용 — 시뮬레이션 없이

`w = exp(β·z)`, `z` = 문항 내 표준화 점수. 무가중 82.83%:

```
β=0.1~0.5   83.04%   **+1문항**   ← **val 잡음 바닥과 동일**
β=0.75      82.83%    ±0
β=1.0       81.96%   **−4문항**
```

**최적점이 잡음 바닥이고 조금만 세게 걸면 손해다.**

### ρ 첫 실측

```
**ρ = 0.304**   (답 군집이 설명하는 점수 분산 비중)
```

같은 답에 도달한 샘플끼리 점수의 30% 가 공유된다. `majority-aware-rl.md` §9 표에서
AUC 0.575 · ρ 0.30 이면 이득 ≈ 0 인데 **예측과 실측이 일치**했다.

### 기록 정정

8/22 에 담화 표지 접전 AUC 를 **0.529** 로 적었으나, 교차적합 어휘 스윕 판본은 **0.565** 다.
손으로 고른 것보다는 낫지만 **문턱 아래**라는 결론은 같다.

### 잔여물

모델이 `confident` 라고 실제로 쓴 샘플의 정답률이 **96.5%** 다. 자기 확신 표명은
정보를 담지만 등장이 **2.7%** 뿐이고 대부분 쉬운 문항이다.

**세로로 거의 안 변한다.** 즉 **v2 확정 관문은 정확도에 기여하지 않는다** —
`확정없음` 과 `v2≥30` 이 전 구간에서 동일하다. 그것이 하는 일은 **문샷 55.6% 생략**,
곧 **순수한 시간 절약**이다. 정확도 +3문항은 전부 **가로축(경시STaR 조건부 증원)**에서 온다.

> **한 카드로 보고했지만 실은 독립적인 두 개다**: ① 시간 반감(무해) ② 정확도 +2~3(조건부 증원).
> 앞으로 이 둘은 따로 검정해야 한다. 묶어두면 한쪽이 죽을 때 다른 쪽까지 잃는다.

**문턱은 봉우리가 아니라 고원이다** — margin 5·8 이 둘 다 +3, 3·12·20·32 가 +2.
데이터를 보고 고른 값이지만 **인접 값이 무너지지 않으므로 과적합이 아니다.**
margin=32(사실상 무조건 3자)도 +2 라, 조건부의 순이득은 **1문항 + 시간**이다.
(3시드로는 무조건 [+5,+1,−1] 평균 +1.7 vs 조건부 [+6,+3,+0] 평균 +3.0 — 조건부가 **분산도 작다**.)

### 20-3. 남은 헤드룸의 지도 — **한 곳에 몰려 있다**

```
캐스케이드 383/460 · 오답 77
  ├ 탐색 실패 31 (gold 가 96표 안에 아예 없음)  → **집계로는 못 건진다**
  └ 회수 가능 46 (gold 가 표 안에 있는데 1위가 아님)
       그중 **28문항이 3단계 지대(69문항)에 몰려 있다**
       3단계 지대 성적: 정답 19/69 (28%) · gold 표 안 47/69 (68%)

완벽 모델 선택기 상한   +8문항  (85.00%)   ← 선택기 축은 **5회 폐쇄**
완벽 수확 상한         +46문항 (93.26%)
```

**캐스케이드가 한 진짜 일은 지대를 특정한 것이다.** val460 의 **15%(69문항)** 안에
회수 가능분의 **61%(28/46)** 가 들어 있다. 정확히 그 지대가 CLAUDE.md 가 기록한

## §21 — 새 축 4개를 만들어 **전부 하루 만에 닫았다** (2026-08-24) · GPU 0

사용자 요청("아예 생소한 축을 만들어 보자")으로 네 개를 설계·측정했다.
**전부 기존 생성물로만 판정했다 — GPU 시간 0.**

### 21-1. ㊸ 자기수정(2턴 재고) — exp-048, 12일간 미분석

`RESULTS.md` 참조. 재고 maj@8 74.5/76.5/74.5% vs 짝 대조군 v2 maj@8 **78.0%**.
기제는 **앵커링**(씨앗 답 95~97% 유지)이라 다양성이 죽는다.
> 첫 계산은 **1샘플 vs maj@8** 이라 표 수 교락이었다(+8 로 보였다). 짝을 맞추니 −7/−3/−7.

### 21-2. ㊹ **멤버 추가는 3에서 포화한다** — 처음 측정

3단계 지대(69문항) 기준, `v2+문샷`(16정답) 위에 멤버를 더한 결과:
```
3번째    contest +3 · baseline +4 · scaled +3 · deficit +2      ← 전부 양수
4번째    최선 조합도 +3, 대부분 +0~+1                            ← 3번째보다 나쁘다
6자      **−1** (기준선보다 낮다)
```
*"모델 2개가 최적"* 은 종전에도 있었으나 **전량 기준**이었다. 접전 지대에서도 같고,
**상한이 3** 임을 처음 쟀다. → **exp-101 의 3단계는 이미 최적점이다. 4번째 모델은 답이 아니다.**

### 21-3. ㊺ **상위2 결선**(제한 결선) — 형태는 새롭지만 신호가 없다

가중·필터가 실패한 이유는 *희석*이다. 그래서 **질량을 무시하고 상위 2후보 중에서만**
제3 실행의 선호로 결정하는 형태를 만들었다 (구조상 희석 불가).
```
para  +1 / +3 / +1  (3시드)      baseline +1
deficit −4 · scaled −1 / −2 · kd −1      → 8개 평균 **−0.25**
```
**형태가 아니라 후보에 의존한다.** 대부분 음수이므로 양수인 것을 고르면 잡음을 고르는 것이다.

### 21-4. **지대 판정의 잡음 바닥을 쟀다 — 이게 오늘의 진짜 소득**

`exp-093` **같은 모델 4시드**가 지대에서 `+3 / 0 / 0 / −1` 이다.
→ **69문항 지대에서 ±3 은 잡음이다.**

이 사실이 위 세 축을 전부 무력화한다. 동시에 **구조적 한계**를 규정한다:
```
지대 69문항 · 오답 50 · 회수 가능 34 (gold 가 192표 합집합 안)
검출 가능한 최소 효과 ≈ 4문항 = 회수 가능분의 **12%**
```
**지대는 효과를 찾기에도 검증하기에도 너무 작다.** 우리가 지대 표적 개입을 여섯 번
"경계 판정" 으로 끝낸 이유가 여기 있다 — 판정력이 없었던 것이지 매번 운이 나빴던 게 아니다.
→ **지대 표적 카드는 앞으로 val 로 채택하지 말 것.** LB 짝 검정(831)이 유일한 판정 수단이다.

### 21-5. 정정 기록

`para` 를 *"재서술된 입력 = 독립 신호"* 로 간주해 *"검산 종결 사유(같은 소스)의 문언 밖"* 이라고
주장했으나 **틀렸다** — manifest 의 `input_digest` 가 표준 val 과 같다.
`para` 는 **시스템 프롬프트만 다른 같은 입력**이고, 프롬프트 축은 이미 닫혀 있다.
> 교훈: **생성물의 정체를 manifest 로 확인하기 전에 기제를 논하지 말 것.**

## §22 — **8/17 결론 정정**: 오답을 세게 만드는 게 아니라 **놓지 못하게 붙든다** (2026-08-24)

§11-9 에 *"확신 강화가 지는 쪽을 더 세게 만든다"* 로 기록했다. **선두 오답의 정의가 편향돼 있었다.**

### 22-1. 무엇이 틀렸나

`v2(s42)` 가 틀린 84문항에서 `선두 오답 Δ` 를 정의별로 재측정했다 (Step-DPO d2).

```
① v2(사전) 기준 선두 오답      **−0.61표**   ← 편향 없음
② d2(사후) 기준 선두 오답      +1.69표      ← 오른 답을 고르는 정의. 순환
③ 두 분포 합산 기준            +0.46표      ← **기록된 +0.49 는 이것**
```

③ 은 선두를 고를 때 **d2 의 분포를 이미 본다**. `gold +0.26` 은 정확히 재현되므로
계산 오류가 아니라 **정의 선택**의 문제다.

당시 회귀-평균 반론을 *"회귀-평균은 gold↑·선두오답↓ 를 예측하는데 실제로는 선두오답이 올랐다"* 로
기각했는데, 편향 없는 정의로는 **정확히 gold↑·선두오답↓ 가 나온다.** 반론이 옳았다.

### 22-2. 올바른 대조군 — **v2 자기 시드**

"v2 가 틀린 문항" 으로 구간을 나눈 순간 회귀-평균이 들어온다. 그러니 기준은 0 이 아니라
**아무것도 바꾸지 않고 다시 뽑았을 때** 다.

```
같은 84문항 · 선두 오답은 v2(s42)로 **사전 고정**
                        gold Δ    선두오답 Δ
v2 자기 시드 s142        +0.23      **−0.95**
v2 자기 시드 s242        +0.48      **−1.50**
Step-DPO d2             +0.26      **−0.61**
beta b03                +0.43      −0.85
```

**학습한 모델이 재뽑기보다 적게 움직인다.** gold 상승은 전부 회귀-평균이고,
선두 오답 이탈은 오히려 **v2 재뽑기의 절반~2/3 수준**이다.

### 22-3. 정정된 기제 — 이것이 "능력↑ 점수↔" 아홉 번의 단일 설명이다

```
학습은 순위를 재배열하지 못한다      1위 답이 v2 와 같은 문항 **89~90%** (d2 90.4 · b03 89.1)
그러면 틀린 1위에서 벗어나는 경로는  **표의 요동**뿐이다 (= 회귀-평균)
확신 강화는 정확히 그 요동을 죽인다  엔트로피 ↓ = 매번 같은 답 = **틀린 1위도 고정**
```

> **오답이 세지는 게 아니라, 탈출로가 막힌다.**

`pass@32`(커버리지)는 확신이 세져도 유지·상승하는데 `maj@32` 는 1위만 읽으므로 안 움직인다.
`exp-079 d4` 의 *"엔트로피 붕괴는 실수를 결정론적으로 만든다"* 가 이 현상의 극단값이었다.

**일반화: `maj@k` 에서 출력 엔트로피는 잡음이 아니라 자산이다.**
엔트로피를 낮추는 개입은 우리가 오답에서 빠져나오는 **유일한 기제와 싸운다.**

### 22-4. 남은 손잡이의 우선순위가 바뀐다

| 손잡이 | 엔트로피 방향 | 기대 |
|---|---|---|
| **NEFTune** (임베딩 잡음) | **↑** | **유일하게 필요한 방향** — 최우선 |
| `label_smoothing` | ↑ (로짓 평탄화) | 같은 계열, 차선 |
| DoRA · rsLoRA · rank · optimizer | 무관 | 예상대로 낮음 |
| KTO (진행 중) | **↓** (실측 −11%) | 낮음 — 사전 등록대로 `Δmargin` 으로 판정 |

### 22-5. 방법론

**"사후에 정의한 대상의 변화량"을 증거로 쓰지 말 것.** 8/14 에 *"baseline 관측값으로 구간을
나누면 회귀-평균이 개선처럼 보인다"* 를 적어놓고, **같은 실수를 '대상 선택' 축에서 반복**했다.
구간(문항 선택)뿐 아니라 **추적 대상(답 선택)** 에도 같은 규칙이 적용된다.
→ **모든 Δ 측정은 대상을 사전 고정하고, 대조군은 "아무것도 안 바꾼 재실행"으로 둘 것.**

가설   CHES 는 **쌍**에서 온다 → 쌍을 안 쓰는 KTO 는 displacement 를 피한다
실측   쌍을 없앴는데 displacement 가 그대로 나타났다 (chosen 과 rejected 가 함께 하락)
```
8/23 설계 문서에 자기 반박으로 적어둔 *"음의 가중은 unlikelihood 항이라 CHES 발생 조건
그 자체"* 가 맞았다. **선호·억제 계열은 손실 형태와 무관하게 닫힌다** —
GRPO · DPO · Step-DPO · β앵커 · 다수결인식 가중 · KTO 로 **6연패**.

### 23-3. 예측을 적어두고 틀린 기록

→ 규칙: **개입의 표적 효과를 논할 때 분포 전체의 폭 변화를 함께 예측할 것.**

## §24 — **기저율 82% 가 모든 전역 개입을 죽인다** (2026-08-25)

§23 에서 KTO 예측이 틀린 이유를 생성물로 추적했다. **§22 를 한 단계 일반화한다.**

### 24-1. 두 가설이 모두 반증됐다

```
가설 A (사전 등록)  억제가 오답 질량을 줄이고 gold 가 그 자리를 받는다
                   → pass@32 ↑ · Δmargin ≈ 0        **틀림** (90.22 · −0.0397)
가설 B (사후)       KTO 는 일반 집중기다 → 이기는 문항에서는 1위(gold)가 올라야
                   → v2 승 구간 Δgold > 0            **틀림** (−0.65)
```

### 24-2. 실측 — **방향이 아니라 크기가 바뀌었다**

`v2(s42)` 의 승패로 가르고, 추적 대상은 **v2 기준 사전 고정**(§22 규칙).

```
구간            문항     Δgold    Δv2선두    Δ꼬리      KTO / 재뽑기 배율
v2 승  KTO      376     −0.65     −0.65     +0.65
      v2재뽑기   376     −0.18     −0.18     +0.18      **3.6배**
v2 패  KTO       84     +0.57     −0.33     −0.24
      v2재뽑기    84     +0.23     −0.95     +0.73      **2.5배**
```

**v2 를 그냥 다시 뽑아도 부호가 같다** (회귀-평균). KTO 는 그 움직임을 **약 3배로 키웠을 뿐**이다.
정답 여부 정보는 전혀 들어가지 않았다 — 오히려 **이득 배율(2.5)이 손실 배율(3.6)보다 작다.**

부수 지표도 정합한다: 고유 답 수 **5.20 → 4.63 (−11%)** (학습 중 엔트로피 −11% 와 일치),
v2 자기 시드는 5.22 로 **불변**. pass@32 커버리지 상실 11문항의 v2 gold 득표는 **3.55표/32** —
전체 평균 25.80표와 비교하면 **꼬리에서 죽었다.**

### 24-3. 원리 — 기저율이 판을 정한다

```
v2 가 이미 맞는 문항   376 (**82%**)   ← 건드리면 잃을 것만 있다
v2 가 틀리는 문항       84 (18%)      ← 건드려야 얻는다

gold 표 총합  376×(−0.65) + 84×(+0.57) = **−196표**
```

> ⚠ **2026-08-25 정정**: *"반드시 진다"* 는 과일반화였다. 정확히는 **교환비 장벽**이다 —
> `ΔAcc=(1−π)r−πb` 이므로 이기려면 **r/b > 376/84 = 4.48**. `exp-100` 은 0.88 이라 졌다.
> 또한 **gold 표 총합은 평가값이 아니다**(평가는 최빈답 Exact Match) — 안전한 문항의 잉여 표를
> 잃고 접전을 뒤집으면 총합이 내려가도 정확도는 오를 수 있다. 상세: `methodology.md` §4-B

**표적성은 학습 문항에 남고 부작용만 새 문항으로 전이된다.** 새 문항에서 모델은
어느 궤적이 오답인지 모르므로, 남는 것은 *"얼마나 많이 움직이는가"* 뿐이다.
전례: `exp-036` DPO2 표적 **+11.11%p** 인데 전체 **−0.65%p** · `exp-074/075` 교환비 3연속.
**세 번 기록해놓고 같은 가정을 다시 했다.**

### 24-4. 이것이 `exp-101` 이 **유일하게 이긴** 이유다

```
전역 개입 (학습·프롬프트·샘플링·가중·KD·선호)   기저율 **82%** 판에서 개입 → 전부 폐쇄
exp-101 3단계 (접전 지대 한정)                기저율 **23%** (16/69) 판에서 개입 → **채택**
```

**원리: 개입은 조건부여야 한다 — 이미 맞는 82% 를 건드리지 않는 형태로.**
닫힌 43개 축의 상당수가 "기법이 나빠서"가 아니라 **게이트가 없어서** 죽었다.

> ⚠ **단, 조건부라고 다 되는 것은 아니다.** §21-4 가 같이 성립한다 —
> 69문항 지대는 ±3 이 잡음이라 **val 로는 판정할 수 없다.** 조건부 카드는 LB 짝 검정으로만 채택한다.

### 24-5. 진행 중인 `exp-103 NEFTune` 에의 함의

NEFTune 도 **전역 개입**이라 이 원리상 불리하다. 다만 판정 기준이 단독 점수가 아니라 **φ** 이고,
파트너는 캐스케이드 안에서 **조건부로만** 소비된다. 사전 등록 게이트를 바꾸지 않는다.

## §25 — 문샷의 길이는 **퇴화가 아니라 혈통**이다 · 절단표의 정체 (2026-08-25)

`exp-104` 착수 중 *"문샷이 왜 토큰을 그렇게 먹나 — 불필요한 반복인가"* 를 실측했다.

### 25-1. 반복이 아니다

```
고유 12-gram 비율   문샷 지대 **0.954** · 지대밖 0.980 · v2 지대 0.970
                   (전형적 퇴화는 0.3~0.5. 0.95 는 거의 다 새 문장이다)
절단 샘플 0.947 vs 완주 샘플 0.969  ← 국소 중복은 있으나 미미
```
표본 판독: 같은 식을 두 번 연달아 쓰는 국소 중복은 실재하나, **잘린 지점은 헤맴이 아니라
대수 전개 도중**이었다. 루프에 빠진 것이 아니다.

### 25-2. R1 혈통의 장사고 화법이다

```
담화 표지 (100만자당)    문샷 지대   문샷 지대밖   v2 지대
wait                     1832       1551       **0**
alternatively             359         407          0
hmm                       174         254          0
```
`wait` 가 v2 는 **0회**다. 문샷은 R1 long-CoT 증류라 **자문자답하며 되짚는 화법**을 물려받았다.
**표지 밀도는 지대 안팎이 거의 같다**(1832 vs 1551) — *어려워서 더 헤매는 게 아니라
같은 스타일로 더 오래 간다.*

```
길이 중앙값   문샷 지대 **19,665자** · 지대밖 5,310자 (3.7배)
             v2  지대   2,126자 · 지대밖 1,084자 (2.0배)
절단 샘플 중앙 21,337자(=상한) vs 완주 14,587자  → 지대에서 8192 토큰이 실제로 모자란다
```

**함의(운영)**: 캐스케이드가 문샷을 55.6% 생략하는 근거가 여기 있다. **단 시간 절감은 10~15%다** — 생략분이 전부 싼 문항이고 남는 문항이 2.07배 비싸다 (*"16.0h→8.1h"* 는 평균 비용 가정의 계산 오류. 2026-08-25 정정).
문샷 비용은 **지대에 집중**되어 있고, 지대 밖에서는 애초에 짧게 끝난다.

### 25-3. 절단표는 나쁜 표다 — **단 인과는 미확정**

```
지대에서   절단된 표 1,474개 중 정답 **4.6%**
          완주한 표   734개 중 정답 **17.3%**   (3.75배)
```
⚠ **이것은 선택 효과일 수 있다.** 잘린 이유가 "오래 걸려서"이고 오래 걸린 이유가 "헤매서"라면,
토큰을 더 준다고 정확해지지 않는다. **관측은 상관이고 `exp-104` 가 인과를 시험한다** —
① 절단율 66.8% → 30% 미만 ② 그때 정확도가 실제로 오르는가.

> 오늘 같은 함정에 두 번 빠졌다(`exp-048` 표 수 교락 · §22 사후 정의). 세 번째는 **미리** 막는다.

3자 풀링    기준 64표 83.26 · 표 수 대조 96표 82.83 · GRPO 96표 **83.26**
           → 대조 대비 +2문항이지만 **현행 64표 대비 +0문항**

**GRPO 축은 다시 열 이유가 없다.** 보존 생성물이 기존 폐쇄를 더 직접적으로 지지한다 —

> **방법론**: 표 수를 맞춘 대조군이 **기준선보다 낮게** 나오면 *"대조 대비 +N"* 이
> *"현행 대비 +N"* 으로 오독된다. **두 기준을 항상 함께 보고할 것.**
