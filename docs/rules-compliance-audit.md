## 회색 지대 ① — LB 문항 2개가 학습 데이터에 있다

**사실**: 배포 3모델의 학습 데이터 68,731샘플을 리더보드 원본 1,000문항과 대조하니 52건이 일치했고,
**그중 실제 채점 대상(831 필터본)은 2문항**이다 (`val-000575` · `val-000787`).
주 모델 STAR 은 **0건**이며, LONGCOT 2건 · STAR-OLY 1건(중복 1)이다.

**조항 대조**: 규칙 5.1b 가 금지하는 것은 *"test.parquet 의 문제를 학습 데이터로 사용하는 것"* 이다.
리더보드 문항의 학습 사용을 금지한 조항은 규칙 어디에도 없다. 10.1a 는 *"테스트 데이터의 정답을
외부에서 확보하여 제출"* 을 금지하는데, 우리 제출 답은 전부 모델 추론 산출물이고 평가 문항의
정답을 조회한 적이 없다 (LB 배포 파일에는 `answer` 컬럼 자체가 없다).

**경위**: 우리 외부 데이터는 `open-r1/OpenR1-Math-220k` 와 `AI-MO/NuminaMath-1.5` 이고,
대회 데이터도 NuminaMath 계열이다. 같은 원천에서 뽑혔으므로 문항이 겹친다. 우리 dedup 절차는
있었으나 완전하지 않았다 — 8/28 에 *"필터본 831 만 대조하고 원본 1,000 은 안 봤다"* 는 절차 결함을
발견해 `build_contest_pool.py` 에서 고쳤고, 그래서 STAR-OLY 는 그 이후 산출물이라 깨끗하다.

**이전 감사가 0건이었던 이유** — 없어서가 아니라 **검사가 약해서**였다. 빌드 시점의 dedup 은
공백만 축약하는 정규화를 썼고, 두 문항은 줄바꿈과 LaTeX 감쌈만 다른 같은 문제였다.

```
LB  val-000787: "A student at Harvard named Kevin was counting his stones by 11. ..."
학습 데이터    : "A student at Harvard named Kevin\nWas counting his stones by $11$\n..."
                 → 공백 축약으로는 불일치 · 영숫자만 남기면 일치
```

같은 파일을 옛 정규화로 재실행하면 지금도 0건이 나온다. 검사 방법의 한계였고,
`build_contest_pool.py` 의 `norm()` 을 강한 정규화로 교정했다.

**암기 이득이 실제로 있었는지 직접 쟀다 (8/30).** 두 문항의 *학습 타깃 답*과 LONGCOT 의
*LB 추론 32표*를 대조했다. 대회 정답은 조회하지 않았다 — 우리 학습 데이터와 우리 출력만 쓴다.

```
val-000787  학습 타깃 21  →  LB 32표: 21이 4표 (91·0과 4표 동률)   1위지만 12.5%
val-000575  학습 타깃  7  →  LB 32표:  7이 2표, 1위는 5(6표)      **타깃을 재현조차 못 함**
```

**암기가 일어나지 않았다.** 암기된 문항이면 30/32 가 나온다. 두 문항 모두 접전 지대의
극단 분산(최다 4표·6표)이고, 캐스케이드에서 이 표는 STAR 32표와 합쳐지므로 기여가 사실상 0이다.
21문항 규모의 같은 검사(회색 지대 ②)도 **57.1% vs 자기 평균 78.04%** 로 같은 결론을 냈다.

**영향**: 831문항 중 2문항 = **0.24%**. 우리 배포 구성의 LB 점수는 668/831 이고, 두 문항을 빼도
순위 판정에 쓰인 짝 검정(+3문항)은 유지된다.

## 회색 지대 ② — 자체 holdout 21문항이 LONGCOT 학습 데이터에 있다

**사실**: 우리 평가용 holdout `val_split_corrected.csv` 460문항 중 **21문항(4.57%)** 이
LONGCOT 학습 데이터에 있다. STAR 과 STAR-OLY 는 0건이다.

**조항 대조**: **규칙 위반이 아니다.** 이 holdout 은 대회 train 에서 우리가 직접 잘라낸 것이고,
train 의 학습 사용은 5.1a 로 허용된다. 이것은 규칙 문제가 아니라 **우리 판정의 무결성** 문제다.

**영향 실측** (같은 생성물로 문항 부분집합만 바꾼 짝 비교):

```
모델          val460 전체        누설 21문항        비누설 439
STAR        379/460 82.39%    17/21  81.0%     362/439 82.46%
LONGCOT     359/460 78.04%    12/21  57.1%     347/439 79.04%
STAR-OLY    379/460 82.39%    18/21  85.7%     361/439 82.23%

캐스케이드    384/460 83.48%                    367/439 83.60%
캐스케이드 − STAR 단독 = +5문항  →  누설 제외 후에도 +5문항 (불변)
```

**누설은 우리 점수를 부풀리지 않았다. 오히려 깎고 있었다.** 학습에서 본 21문항에서 LONGCOT 은
**57.1%** 로 자기 평균(78.04%)보다 **21%p 낮다** — 암기 이득이 없다. 이 문항들이 OpenR1 에 있다는
것 자체가 «경시 난이도» 라는 뜻이고, 어려워서 학습에서 봐도 못 푼다. 누설 21문항을 제외하면
캐스케이드는 83.48% → **83.60%** 로 오히려 오르며, 채택 판정(+5문항)은 **바뀌지 않는다**.

## 회색 지대 ③ — 운영진 오류 목록 627문항 중 439개가 STAR 학습 데이터에 남아 있다

**사실**: 8/03 공지의 `train_filtered_ids.csv` 627문항 중 `train_split` 에 속한 600개를 기준으로,
주 모델 STAR 의 학습 데이터에 **439개(73.2%)** 가 남아 있다. LONGCOT 68개 · STAR-OLY 0개.

**조항 대조**: 공지 문언은 *"학습 시 해당 문항을 제외하고 활용해 주시기 바랍니다"* 로 **권고**이며,
규칙 4·5 에 이를 금지하는 조항은 없다. 방향도 우리에게 **불리한** 쪽이다 — 라벨이 틀린 문항으로
학습하는 것은 손해지 이득이 아니다.

**경위**: STAR 의 학습 데이터는 8/2 에 확정됐고 627 목록은 **8/3 14:00 에 공개**됐다.
우리는 STaR(자기생성 + 정답 일치 필터)이라 결함 문항이 자동으로 걸러질 것으로 봤으나,
실제 표본을 읽으니 세 가지 경로로 통과했다:

- **`train-013514`** — 채택된 해설이 `\boxed{d}` 로 끝난다. 비정수 답인데 파서의 fallback 이
  본문 중간의 숫자를 집어 gold 와 맞춰버렸다.
- **`train-012802`** — *"As shown in the figure"* 로 그림 없이는 풀 수 없는 문항인데 우연히 맞았다.
  잔존 439개 중 **173개가 이미지·그림 참조형**이다.
- **`train-011076`** — *"Given the problem's symmetry ... we conclude: \boxed{2}"* — 추론 없이
  답만 맞춘 전형적 false positive.

**정직한 진술 — 인접 실험은 이 축을 덮지 못했다.** 우리는 라벨 정화 재학습을 실제로 했고
(`exp-087`~`exp-090`: val 4시드 ±0.0 · LB 짝 검정 663 vs 665 = −2문항) 이득이 없어 폐쇄했다.
그러나 감사 중 확인하니 **그 정화본(`sft_v2_clean`)에도 627 중 427개가 남아 있었다** —
우리 정화는 라벨 오류 *제보 목록* 기준이었고 운영진 목록과 12개만 겹쳤다. 따라서
**「627 을 제거한 재학습」은 한 번도 수행하지 않았다.** *"이미 시험했다"* 고 말할 수 없다.

**조치**: D-2 시점이고 규칙 위반이 아니며, 재학습하면 챔피언 구성이 바뀌어 LB 짝 검정을 처음부터
다시 해야 한다(잔여 제출 한도로 불가능). 따라서 **구성을 바꾸지 않고 사실을 공개한다.**
같은 축의 인접 실험 4건이 전부 ±0~−2문항이었다는 점은 기대 이득이 작다는 정황이다.
