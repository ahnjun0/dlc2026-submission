# 분산이 지배 변수다 — 「능력↑ 점수↔」의 정량적 답 (2026-08-27)

`exp-120` 이 제3의 체제(`n_eff` 5.12)를 만들면서 우리 모델들이 **분산 축에서 넓게 퍼졌다.**
그 덕에 두 달간 열다섯 번 만난 현상을 **상관으로 표현**할 수 있게 됐다.

## 1. 관측 (val 460 · 32표 · 시드 42 고정)

```text
모델                   길이     n_eff   고유답   maj@32   pass@32   gold표/32
경시STaR            1,175자    2.70    4.75   82.39%   91.52%     23.72
KTO                1,169자    2.76    4.79   81.30%   92.61%     23.57
NEFTune            1,179자    3.01    5.12   80.43%   92.61%     23.43
무학습 베이스          1,170자    3.06    5.32   81.30%   91.30%     23.34
v2                 1,152자    3.08    5.20   81.96%   90.87%     23.44
문샷                6,106자    3.59    6.74   77.61%   91.30%     21.20
문샷LoRA            5,983자    3.59    6.87   77.39%   91.30%     20.92
**exp-120(ep1.4)   1,956자    5.03    9.17   75.00%   88.04%     17.93**
**exp-120(ep2)     1,976자    5.12    9.29   75.00%   89.35%     17.81**
```

## 2. 지배 변수는 **분산**이지 능력이 아니다

**능력이 비슷한 7개 모델**(exp-120 제외 · `pass@32` 90.87~92.61%)에서:
```text
pass@32 ↔ maj@32   r = **+0.134**   ← 능력은 점수를 거의 예측 못 한다
n_eff   ↔ maj@32   r = **−0.920**   ← 분산이 점수를 결정한다
```

**이것이 «능력↑ 점수↔» 를 상관으로 표현한 것이다.** 두 달간 우리가 올린 것은 `pass@32`(r=0.134)이고,
점수를 지배하는 것은 `n_eff`(r=−0.920)였다. 15번의 실패가 왜 그랬는지에 대한 정량적 답이다.

9개 전체에서도 `n_eff ↔ maj@32 = −0.939` · `n_eff ↔ gold표 = −0.987` 로 유지된다.

## 3. **길이는 원인이 아니다** — exp-120 이 그 가설을 깼다

```text
7개 모델만 볼 때   길이 ↔ n_eff   r = **+0.912**   ← 길이가 원인처럼 보였다
exp-120 을 넣으면               r = **+0.185**   ← **무너진다**
```
**exp-120 은 1,976자로 짧은데 `n_eff` 5.12 로 가장 흩어지고, 문샷은 3배 긴데 3.59 다.**

→ 분산은 **길이의 부산물이 아니라 학습 체제의 독립 성질**이다.
   `exp-120` 실패를 «중간 길이가 나쁘다» 로 읽으면 틀린다.
   정확히는 **«이 학습 체제가 유독 흩어진다»** 이고, 길이는 무관하다.

## 4. 함의

**① 설계 목표가 바뀐다.** 「더 잘 푸는 모델」(`pass@32`)이 아니라
**「같은 능력에서 덜 흩어지는 모델」**(`n_eff`)이 `maj@k` 배포의 목표다.
그리고 우리가 두 달간 최적화한 것은 전자였다.

**② 최적점은 없다 — 단조 감소다.** `n_eff` 2.70~5.12 구간에서 포물선이 아니라
직선적 악화다. **분산은 순수한 손해**이므로 «적당한 다양성» 을 추구할 이유가 없다.
다양성은 **모델 간**(오답 비상관)에서 얻고 **모델 내**(표 분산)에서는 줄여야 한다.

**③ 파트너 선정 규칙.** ⚠ **§11 에서 정정됨** — 종전에 여기 적었던
*«모델 간 다양성 ↑ · 모델 내 분산 ↓»* 는 **주 모델에만 맞다.**
파트너 자리에서는 `n_eff` 가 **클수록** 기여가 크다(r +0.946, 정점 ≈3.6 까지).
`LITECOT`(5.12)이 실패하는 이유는 분산이 높아서가 아니라 **정점을 넘겨 gold 표 공급이
무너져서**다(21.20 → 17.81). 정확한 조건은 **«다르되, 자기 답에는 모여야»** 다.

## 5. 한계 (반드시 함께 적을 것)

```text
· n = 7~9 로 작다. **시사이지 확정이 아니다.**
· `n_eff ↔ gold표 −0.987` 은 **부분적으로 산술**이다 — 표가 흩어지면 어느 답이든 표가 준다.
  새로운 것은 «n_eff 가 모델마다 크게 다르고 그것이 pass@32 보다 점수를 잘 예측한다» 이다.
· 한 시드(42) · 한 평가셋(val460, 낙관 편향 확인됨)이다.
· exp-120 은 극단점이라 **지렛대 효과**가 크다. 그것을 빼면 상관이 달라진다(§3).
```

## 6. 배포에 쓸 데가 있는가 — 세 갈래를 다 재봤다

### 6-1. 소수 답 가지치기 — **정확히 0**
```text
없음(현행) 387 · 득표 ≤1 버림 387 · ≤2 버림 387 · ≤3 버림 387   (평균 n_eff 4.08 → 2.00)
```
**분산을 절반으로 줄여도 답이 한 문항도 안 바뀐다.** 소수 표는 애초에 최빈이 될 수 없다.
«분산이 나쁘다» 는 **모델의 성질**이지 **집계 시점에 고칠 수 있는 것**이 아니다.

### 6-2. `n_eff` 의 오답 감지력 — 접전에서도 살아 있다 (다만 «감지»다)
```text
지대            문항   정답률   n_eff AUC   top_share AUC   n_eff 중앙
1단계 확정       249   99.6%     0.8367       0.8367        1.00
2단계           150   79.3%     0.8550       0.8715        2.35
**3단계 접전**    61   32.8%     0.7098       0.7585       12.45
전체            460   84.1%     0.9442       0.9501        1.13
```
전역 0.944 는 자명하다(«확신하면 맞는다»). **접전에서 0.71 이 살아 있는 것**이 유의미하며,
8/25 기록과 정합한다 — **«1위가 틀렸음을 감지»는 되고(0.63~0.79) «올바른 대안 식별»은 안 된다(0.5338)**.

### 6-3. `n_eff` 를 3단계 방아쇠로 — **격차보다 낫다. 다만 문턱 미달**
```text
격차 ≤5 (현행)    385.00   발동 64.7
**n_eff ≥5       386.00   발동 89.3**

교차적합 (문항 단위 폴드 5분할 · 문턱을 학습)
  격차 문턱 학습   **−1.67**   ← gap=5 는 이미 최적이라 학습하면 과적합한다
  **n_eff 문턱 학습  +1.00**   ← 실재하는 개선 (3단계 오라클 +2.67 의 37%)
```
**변수 자체가 더 낫다** — 격차는 배울 것이 없는데 `n_eff` 는 교차적합에서도 이득이 남는다.

> ⚠ **정정 (같은 날 EDA)**: 위 `+1.00` 은 **거친 격자(7개 값)** 에서 나온 값이다.
> **세밀 격자(0.5 간격 21개 값)로 다시 교차적합하면 `+0.00`** 이다 —
> 고를 후보가 많아질수록 **선택 잡음**이 커지고 이득(+1)이 그보다 작다.
> **정직한 값은 0 이다.** 결합 방아쇠(`AND(gap≤5, n_eff≥3)`)도 교차적합 +0.33 으로 같다.
> §7 참조.

**그래도 채택하지 않는다**: +1.00 은 실용 최소효과(+3) 미만이고,
val→LB 전이 부족(−2.4~−4.3문항, 6건 전부 같은 방향)을 감안하면 **LB 기대가 음수**다.
제출 한 번을 쓸 값어치가 없다. **D-4 에 검증되지 않은 방아쇠로 668 을 바꾸지 않는다.**

> **남겨두는 이유**: 시간이 더 있었다면 이것이 다음 LB 후보였다.
> 3단계 방아쇠 축에서 **교차적합 양수를 낸 유일한 변수**다
> (고유답수 +0.50 · 구조 분할 −0.67 · 지도 학습 −2.00 · 군집 −4.00 중에서).

**산출물**: `src/eval/{dispersion_law,neff_zone,neff_trigger}.py`

## 7. `n_eff` EDA — 변수는 좋은데 쓸 형태가 없다 (2026-08-27)

### 7-1. `n_eff` 는 중복이 아니고, **현행 방아쇠(격차)가 셋 중 최악**이다

```text
상관 (2단계 진입 208문항/시드)
  **gap ↔ p_share    r = +0.957**   ← 격차와 최상위 점유는 사실상 같은 변수다
  p_neff ↔ gap       r = −0.627
  p_neff ↔ p_share   r = −0.766     ← `n_eff` 는 **다른 정보**를 담는다

«3단계가 도움 되는가» 판별력 (도움 17 · 해로움 11 · n=28)
  **p_neff  AUC 0.8556**
  p_share   AUC 0.8422
  **gap     AUC 0.5936**   ← 우리가 실제로 쓰는 변수
```
**우리 방아쇠는 «3단계가 도움 될지» 를 거의 예측하지 못한다(0.59).** (단 n=28 로 잡음이 크다.)

### 7-2. 그런데 문턱 선택이 교차적합을 못 넘는다 — **격자 크기에 의존한다**

```text
세밀 스윕 (0.5 간격) 최고   n_eff ≥5.0 / ≥5.5 = **386.00**   (현행 gap≤5 = 385.00)
교차적합 (문항 폴드 5분할)
  gap 문턱 학습     **−1.67**   ← gap=5 는 이미 최적이라 학습하면 과적합
  **n_eff 문턱 학습  +0.00**    ← 거친 격자(7개)에서는 +1.00 이었다
  결합 AND/OR       +0.33
```
**«고를 후보가 많아질수록 선택 잡음이 커진다»** 의 교과서적 사례다.
거친 격자의 +1.00 은 **격자를 작게 잡아서 생긴 값**이었고, 정직한 값은 **0** 이다.

### 7-3. 1단계에 쓰면 **시간 카드**가 된다 (정확도 카드는 아니다)

```text
1단계 기준          평균 정답   문샷 호출
최다 ≥30 (현행)     385.00     **45%**
n_eff ≤2.0         385.00      29%
**n_eff ≤2.5       385.67      25%**
```
`sub-016`(`confirm=16`, 호출 22%)과 같은 계열이며 정확도는 오히려 +0.67 이다.
**그러나 `sub-016` 은 LB 에서 −2 였다** — val 평지가 LB 평지를 뜻하지 않는다.
그리고 우리는 이미 «시간이 필요 없으면 안 바꾼다» 로 결론냈다(`docs/dday-protocol.md`).

### 7-4. 결론

**변수는 좋은데 그것을 쓰는 형태가 «문턱 하나» 뿐이라 살릴 수 없다.**
3단계 축에서 시도한 아홉 번째이며 결론이 같다 —
**감지는 되는데(AUC 0.86) 행동으로 전환되지 않는다(교차적합 0.00).**

**산출물**: `src/eval/neff_eda.py`

## 8. `n_eff` 를 문턱이 아닌 형태로 — **네 형태 전부 시험, 전부 미달**

문턱이 교차적합 0 이었으므로 변수의 판별력(AUC 0.86)을 살릴 다른 형태를 찾았다.
**전부 문항 단위 폴드 교차적합으로만 판정했다.**

```text
① 문턱 (0.5 간격 21값)              **+0.00**
② **모델별·문항별 가중** (w=1/n_eff^α)  **−0.67**   α ∈ {0.25 … 2.0} 전부 현행 이하
③ 2위 응집도 (1위 뺀 나머지의 분산)     새 정보 아님 — 아래 참조
④ 이진 분류기 (n_eff+share / 7특징)   **+0.67**
```

**②는 «가중 투표» 축의 재확인이다.** 8/1 에 «균일 투표가 전 방식 이상»(길이·검산문구·추출경로)
이었는데, **모델별·문항별 분산이라는 새 특징으로도 같은 결론**이다.

**③은 부호가 뒤집혀 있었다**: «1위가 틀렸는가» 에 대해 `rest_neff` AUC 0.31 · `rest_top` 0.30 —
뒤집어 읽으면 0.69/0.70 이고, 이는 **«나머지가 흩어질수록 1위도 틀렸다»** 즉
**전반적 난이도의 재표현**이지 «진짜 경쟁자가 있다» 는 신호가 아니다.

### 왜 어떤 형태로도 안 되는가 — **행동 공간이 병목이다**

```text
3단계 지대 194건(64/시드) 중
  3단계를 켜서 **이득 17 · 손해 8 · 무변화 169 (87%)**

안 켬 16.67  ·  **현행(전부 켬) 19.67**  ·  오라클(문항별 최선) **22.33**
```
**87%가 무변화다.** 판별기가 완벽해도 바꿀 수 있는 것은 **25건**뿐이고
상한이 **+2.67**(실용 최소효과 +3 미만)이다. 그리고 AUC 0.86 은 그 25건에서 잰 값이라
학습이 일반화되지 않아 실제로는 +0.67 만 건진다.

> **오늘 만난 것의 가장 깨끗한 형태다** — *병목은 판별기의 품질이 아니라 **행동 공간의 크기**다.*
> 「감지는 되는데 행동으로 이어지지 않는다」의 정확한 정의가 이것이다:
> **감지할 대상이 25건뿐이면 AUC 0.86 도 +0.67 이 된다.**

**산출물**: `src/eval/{neff_eda,neff_forms,neff_classifier}.py`

```
① 행동 공간이 작다     61문항 중 7~11건
② **전환율이 0% 다**   여지 +6 이 있어도 못 잡는다
```

**7후보 × 5분할 교차적합 = 35회에서 양수가 하나도 없다.** ②가 더 근본적이다.
`exp-110` 의 «전환 효율 21%» 가 여기서는 **0%** 다.

|---|---|---|
| 최다 ≥24 | 385.00 | 32% |
| **최다 ≥30 (현행)** | **385.00** | **45%** |
| 최다 ≥32 | 385.00 | 58% |
| n_eff ≤2.5 | 385.67 | 25% |
| n_eff ≤2.3 (격자 최고) | 385.67 | 27% |

**교차적합**: 최다득표 문턱 **+0.00** · `n_eff` **+0.33**.
격자 최고 +0.67 이 교차적합에서 반토막 나는 것은 8/25 «성긴 격자 인공물» 과 같은 패턴이다.

**부수 소득 — 1단계 문턱은 점수에 완전히 평평하다.** `≥24` 와 `≥30` 이 소수점까지 같고
문샷 호출만 45%→32% 다. **시간 fallback 후보**로 보관한다(단 `sub-016` confirm=16 이
LB −2 였던 축이므로 시간이 모자랄 때만).

### 9-4. 결론

`n_eff` 축은 **3단계·1단계 양쪽에서, 네 형태 + 7개 3단계 후보 전부 미달**로 종결한다.
행동 공간을 키우려는 두 시도(모델 교체·단계 이동)가 둘 다 실패했으므로,
**판별기 개선이 아니라 행동 공간 자체가 이 대회 규칙 아래서 3~5% 로 고정**돼 있다는
`docs/methodology.md` §4-C 의 결론이 재확인됐다.

### 9-5. 비용 지름길로도 진다 — `n_eff` 분기의 최종 판정

§9-3 은 «점수 게이트» 축이었다. 남은 질문은 **비용 지름길**로서 최다득표 문턱을 이기는가다.
판정 기준은 점수가 아니라 **«답 변경 0»** 이다 (`src/eval/confirm_sweep.py`).

| 1단계 기준 | **답 변경** | 2단계 호출 |
|---|---|---|
| 최다 ≥30 (현행) | 0 | 993 (45%) |
| **최다 ≥22** | **0** | **653 (30%)** |
| n_eff ≤1.8 | 0 | 700 (32%) |
| n_eff ≤2.0 | **2** | 652 (29%) |
| n_eff ≤2.3 | 4 | 587 (27%) |
| n_eff ≤2.5 | 7 | 554 (25%) |

**같은 호출률(≈30%)에서 최다득표는 답을 안 바꾸고 `n_eff` 는 바꾼다 — 지배당한다.**

### 9-6. 기제 — 왜 더 좋은 판별기가 더 나쁜 결정을 하는가

`n_eff` 는 «3단계가 도움이 될까» AUC **0.8556** 으로 배포 중인 `gap`(0.5936)보다 훨씬 낫다.
그런데 배포에서는 진다. 이유는 두 변수가 **다른 종류의 정보**이기 때문이다.

```text
최다득표   뒤집힘의 **상한을 산술적으로 준다**
           v2 가 22표면 문샷 32표로 못 넘는다 (실측 풀 마진 중앙 24~30표)
n_eff      **상관일 뿐이다**
           15/15/2 는 n_eff 2.1 로 낮은데 최다가 15표라 쉽게 뒤집힌다
```

> **`n_eff` 는 «모델을 고르는 자»로는 최고(r −0.920)이고, «문항을 가르는 자»로는 못 쓴다.**
> 배포 결정에는 상관이 아니라 **보증**이 필요하다.

이것이 「감지는 되나 행동으로 연결되지 않는다」의 가장 선명한 사례다 —
여기서는 판별력의 우위가 **측정됐는데도** 결정에서 졌다.

## 10. 법칙의 한계 — 좁은 띠 안에서는 예측하지 못한다 (2026-08-27)

사용자 질문: *「경시STaR 이 v2 보다 항상 좋으면 주 모델을 바꿀 이유가 없나?」*

### 10-1. 단독 우위는 **한 시드의 운**이었다

```text
시드     v2  maj/pass/n_eff        경시  maj/pass/n_eff      Δmaj
s42     81.96  90.87  3.08        82.39  91.52  2.70        **+2문항**
s142    81.30  90.87  3.02        81.30  90.87  2.77         +0
s242    81.30  92.17  3.03        81.09  91.52  2.77        **−1문항**

Δmaj  평균 **+0.33문항** · 양수 시드 **1/3**
Δpass 평균 **+0.00%p** ([+0.65, 0.00, −0.65])
```
**관문 ③(주 모델 시드 복제)이 또 작동했다.** §1 표가 s42 고정이라 우위가 실재하는 것처럼 보였다.

### 10-2. 캐스케이드에서는 **−3.00문항** (이미 측정됨, `why-cascade-works` §7-1)

주 모델은 단독 점수만으로 정해지지 않는다 — ① 1단계 확정 판정 ② 동률 우선권
③ 64/96표 중 32표 공급을 겸한다. 경시STaR 를 앞으로 빼면 **v2 가 3번째 자리로 밀리는데**,
그 자리의 v2 재뽑기는 **+1.67** 로 경시STaR 의 **+3.00** 보다 작다. **자리마다 요구가 다르다.**

### 10-3. ⚠ 그리고 이것이 **법칙의 한계**다

경시STaR 의 `n_eff` 는 **세 시드 전부** v2 보다 낮은데(2.70/2.77/2.77 vs 3.08/3.02/3.03)
`maj@32` 는 **동률**이다. 법칙대로면 이겨야 한다.

> **법칙은 `n_eff` 2.70~5.12 의 넓은 구간에서 잰 «체제 간» 관계이지,
> 2.77 대 3.03 같은 «좁은 띠 안»의 예측자가 아니다.**

§5 의 한계 목록에 이것을 추가한다. **발표에서 반드시 함께 말할 것** —
빼놓으면 「`n_eff` 낮은 모델을 고르면 된다」로 오독된다. 정확한 주장은
**「체제를 고를 때 능력보다 분산을 봐라」** 이고, **「분산이 0.3 낮은 모델이 더 낫다」가 아니다.**

산출물: `src/eval/contest_vs_v2.py`

## 11. ⚠ 정정 — 파트너 자리에서는 부호가 **뒤집힌다** (2026-08-27)

사용자 질문: *「모델 내부에서는 `n_eff` 가 낮을수록 좋은데, 풀링할 때는 클수록 좋다는 건가?」*

§4-③ 에 *「다양성은 모델 간에서 얻고 **모델 내 분산은 줄여야 한다**」* 라고 적었다.
근거는 두 점(`LONGCOT` 3.59 좋음 / `LITECOT` 5.12 나쁨)뿐이었고,
**`LONGCOT` 의 `n_eff` 가 주 모델 `STAR`(3.08)보다 높다는 사실을 그냥 지나쳤다.**
후보 8개로 다시 쟀다 (`src/eval/partner_neff.py`).

### 11-1. 역U자다

| 파트너 | `n_eff` | 단독% | 충돌률% | **기여(문항)** |
|---|---|---|---|---|
| **LONGCOT** | 3.59 | 77.61 | 28.2 | **+6** |
| LONGCOT-LoRA | 3.59 | 77.39 | 34.8 | **+5** |
| STAR+NEFT | 3.01 | 80.43 | 65.4 | +4 |
| BASE | 3.06 | 81.30 | 59.7 | +3 |
| STAR (재뽑기) | 3.03 | 81.30 | 58.1 | +3 |
| STAR-OLY | 2.70 | 82.39 | 66.2 | +2 |
| STAR+KTO | 2.76 | 81.30 | 57.5 | +2 |
| **LITECOT** | **5.12** | 75.00 | 35.1 | **+0** |

```text
LITECOT 포함 (n=8)   n_eff ↔ 기여   r = **-0.310**
LITECOT 제외 (n=7)   n_eff ↔ 기여   r = **+0.946**   ← 정점 이전 구간
```

**주 모델 자리와 파트너 자리가 반대 방향을 요구한다.**
```text
주 모델   n_eff ↓  →  maj@32 ↑     (r -0.920, §2)
파트너    n_eff ↑  →  기여   ↑     (r +0.946, 정점 ≈3.6 까지)
```

### 11-2. 기제 — 충돌률을 통제하면 보인다

| 파트너 | `n_eff` | 충돌률% | **gold표/32** | 기여 |
|---|---|---|---|---|
| LONGCOT | 3.59 | 28.2 | 21.20 | +6 |
| LONGCOT-LoRA | 3.59 | 34.8 | 20.92 | +5 |
| **LITECOT** | **5.12** | 35.1 | **17.81** | **+0** |

**다양성은 셋이 비슷한데(28~35%) `LITECOT` 만 0 이다.** 차이는 **gold 표 공급량**이다 —
다르긴 한데 **자기 표가 뭉치지 못해** 주 모델의 오답을 이길 표를 못 낸다.

> **파트너는 「다르되, 자기 답에는 모여야」 한다.**
> 다양성은 문을 열어줄 뿐이고, 문 안에서 이기려면 표가 뭉쳐야 한다.

### 11-3. 한계 (반드시 함께 적을 것)

```text
· n = 7~8 · **단일 시드(s42)** · 문항 460
· n=7 구간에서 n_eff·충돌률·단독성능이 서로 |r| > 0.84 로 **공선**이다
  → 「n_eff 만 떼어냈다」고 주장할 수 없다. 11-2 의 통제 비교가 더 나은 증거이나 n=3 이다
· 「정점 3.6」은 관측된 두 값(3.59, 5.12) 사이 어딘가라는 뜻이지 추정치가 아니다
```

**그럼에도 §4-③ 의 문장은 정정한다** — *「모델 내 분산을 줄여라」* 는 **주 모델에만** 맞다.

## 12. 자리별 요구 — §11 의 요약을 좁힌다 (2026-08-27, 사용자 질문 3건)

§11 끝에 *「파트너는 다르되 자기 답에는 모여야 한다」* 라고 적었다. **3단계 자리에서 깨진다.**

### 12-1. `STAR-OLY` 의 우위는 **주제**에서 온다 (`src/eval/oly_hypothesis.py`)

사용자 가설: *「경시 분포로 학습했으니 실제로 그런 문항을 더 맞혀서 아닌가」* — **맞다.**

```text
① 단독 정확도 (3시드)   STAR-OLY − STAR    경시형 **+1.30%p**  ·  그 외 **−0.40%p**
② 지대의 주제 구성      경시형 128문항 중 41 (**32.3%**)가 접전 · 그 외 332 중 23 (7.0%)
                       → 지대는 경시형 **64%**, val 전체는 28%
③ 지대 기여            STAR-OLY  경시형 **+4.00** / 그 외 **−1.00**
                       STAR재뽑기 경시형  +2.00  / 그 외  +0.67
```
**두 자리의 측정이 어긋났던 이유가 이것이다** — 2단계는 대부분 비경시형이라 우위가
희석되고 `−0.40` 이 비용으로 잡혀 **+2**, 3단계 지대는 64%가 경시형이라 농축돼 **+3.00**.

> ⚠ **캐스케이드는 결과적으로 주제 라우터처럼 작동한다** — 단 **입력이 표 구조뿐**이고
> 주제 농축은 «어려운 문항이 경시형에 몰려 있다」의 **부산물**이다. 발표에서 이 사실을
> 이 사실을 함께 밝히고, 분기 변수가 주제가 아님을 보인다 (규칙 4.3 대응).

### 12-2. 2단계에서는 분산이 실제로 작동한다 (`src/eval/slot_requirements.py`)

기여 = **구제**(주 모델이 틀린 문항을 살림) − **파괴**(맞던 문항을 깸).

```text
2단계 자리   n_eff ↔ **구제**  r = **+0.802**      n_eff ↔ **파괴**  r = +0.289
             흩어진 파트너는 더 많이 구하고 더 많이 깨는데, **구제가 더 빨리 는다**
             LONGCOT 구제 11 / 파괴 5 = +6   ·   STAR-OLY 6 / 4 = +2
```

### 12-3. 3단계에서는 분산이 **순서를 못 만든다**

지대 안에서 잰 `n_eff` 는 9.16~11.19 인데 기여와 무관하다.
```text
STAR-OLY   n_eff 9.16   구제 6 / 파괴 2 = **+4**   ← 가장 낮은 n_eff 인데 최선
STAR재뽑기   n_eff 11.08  구제 5 / 파괴 2 = +3
BASE       n_eff 11.19  구제 5 / 파괴 6 = −1
LONGCOT-LoRA n_eff 10.43 구제 2 / 파괴 6 = **−4**
```

### 12-4. ✗ 반증된 설명 — 「두 자리의 병목이 다르다」

*「2단계는 탐색 실패, 3단계는 회수 실패가 병목」* 이라는 설명을 세웠다가 재보고 **버렸다**.

```text
2단계 진입 전체   오답 76 중 gold 가 표 안에 있음  44 (**58%**)
3단계 접전 지대   오답 45 중 gold 가 표 안에 있음  25 (**56%**)
```
**병목 구성이 사실상 같다.** 설명이 성립하지 않는다.

### 12-5. 그래서 정확한 진술

```text
주 모델      n_eff 낮을수록 좋다                     (r -0.920, §2)
2단계 파트너  n_eff 높을수록 좋다 (정점 ≈3.6 까지)     (r +0.946 / 구제 r +0.802, §11·12-2)
3단계 멤버   n_eff 은 **무관**. **그 지대를 실제로 잘 푸는 모델**이 이긴다 (12-1·12-3)
```
> **§11 의 「파트너는 흩어지되…」는 2단계 자리에 한정한다.**
> 3단계에 대한 통일 설명은 아직 없다 — 관측은 «주제 적합» 이고, 그 이상은 주장하지 않는다.

## 13. 「접전 지대와 유사한 train 문항으로 3단계 멤버를 재학습」 검토 (2026-08-27)

사용자 제안: `STAR-OLY` 를 경시대회로 한정하지 말고, **1·2단계에서 결론 안 난 문항과
유사한 문항**을 train 에서 뽑아(벡터 유사도) 재학습.

**표적 설정은 옳다** — 경시 분포는 접전 지대의 대리 변수일 뿐이다(§12-1).
그러나 구성 요소가 전부 이미 측정돼 있다.

| 제안의 요소 | 이미 한 것 | 결과 |
|---|---|---|
| **임베딩 유사도**로 풀 선정 | `exp-034` | **기각** — *"임베딩 거리·길이·어휘 중복은 「이 모델에게 무엇이 어려운가」를 반영하지 못한다"* |
| 대신 쓰는 자 = **해결률** | `exp-034` | 채택. `star_solve_stats.csv` 에 train 16,500문항 `n_ok` 보유 |
| **문항 단위 frontier 선별** | `exp-035` (=`STAR-OLY`) | **이미 구현** — 해결률 역비례 채택 `easy 1 / mid 2 / frontier 4` + 독립 시드 재확인 |
| train 미사용분 **재채굴** | `exp-113/114/116` | **−4.00문항** |
| train **재가중**(같은 데이터) | v3 · v5a | −0.4 / ±0 (무정보형 사분면) |

### 13-1. 대리 변수가 이미 충분히 좋다 (`src/eval/zone_proxy.py`)

val 460×3시드에서 **v2 해결률 → 「3단계 지대인가」 AUC = 0.949**.

| v2 해결률 | 문항/시드 | 지대 | 지대 비율 |
|---|---|---|---|
| 0 | 40 | 25 | 63.3% |
| ≤3/32 | 26 | 16 | 63.3% |
| ≤8/32 | 18 | 11 | 61.1% |
| ≤16/32 | 33 | 10 | 30.7% |
| ≤24/32 | 39 | 1 | 3.4% |
| **>24/32** | **303** | **0** | **0.0%** |

**지대의 81%(52/64)가 `≤8/32` 구간에 있고, `exp-035` 는 그 구간에 가중치 4배를 준다.**
즉 `STAR-OLY` 는 이미 접전 지대를 겨냥해 만들어진 모델이다.

### 13-2. 진짜 새로운 판본은 감당이 안 된다

「캐스케이드 접전」을 직접 기준으로 쓰려면 **train 전량에 문샷 생성**이 필요하다 —
문샷은 7배 느려 16,500문항이면 **50 GPU시간 이상**이다. 그렇게 골라도 AUC 0.949 로
거의 같은 문항이 뽑힌다.

### 13-3. 그리고 풀의 출처가 결정적이다

`exp-035` 가 작동한 이유는 **외부 경시 풀 = 새 문제**였기 때문이다.
train 부분집합으로 재학습하는 것은 **v2 가 이미 학습한 데이터의 재가중**이라
「무정보형」 사분면(v3 −0.4 · v5a ±0)에 들어간다.

**판정: 미착수.** 표적은 옳으나 실행 가능한 판본은 전부 닫혀 있고, 닫히지 않은 판본은
50 GPU시간을 써서 같은 데이터를 뽑는다. D-4 에 SFT 축(0승 10패)을 다시 여는 근거가 못 된다.

### 13-4. AUC 0.949 감사 — 순환인가 신호인가 (`src/eval/zone_proxy_audit.py`)

지대는 **v2 의 표 구조**로 정의되는데 해결률도 **같은 v2 샘플**에서 계산했다.
v2 가 30/32 를 맞히면 최다 득표 ≥30 이라 **정의상** 1단계 확정 = 지대 아님.
8/14 규칙 *「baseline 관측값으로 구간을 나누지 말 것」* 에 걸리는 형태다. 분해했다.

| 측정 | AUC |
|---|---|
| ① 같은 시드 (원본 — 순환 포함) | 0.9487 |
| ② **교차 시드** (지대는 s42/s142/s242, 해결률은 **s342**) | **0.9450** |
| ③ 2단계 진입분만 + 교차 시드 | 0.8500 |

```text
① → ② 로 잃은 것  **-0.0037**   = 순환 성분   → **순환이 아니다**
② → ③ 로 잃은 것   -0.0950     = 1단계 관문이 설명하던 몫
```
**문항 수준의 실제 신호다** — 「이 문항이 어렵다」가 시드를 넘어 재현된다.

### 13-5. ⚠ 그러나 AUC 는 이 주장에 맞는 자가 아니다

기저율이 **14.1%** 다. 그 조건에서 AUC 가 높아도 «지대를 특정한다» 가 성립하지 않는다.

```text
「≤8/32 를 뽑는다」   선택 85문항/시드 중 지대 52  →  **정밀도 62.0%**
                    지대 64 중 52 포착           →  **재현율 81.4%**
```
**뽑은 것의 38%는 지대가 아니다.** 이것이 AUC 뒤에 숨어 있던 숫자다.

> **자를 목적에 맞춰 고를 것** — 8/15 에 적은 *「AUC 를 채택 근거로 쓰지 말 것」* 의 재확인이다.
> **판정**(어느 문항에 개입할까)에는 정밀도가 필요하고,
> **데이터 선별**에는 **농축률**만 있으면 된다.

```text
기저율 14.1%  →  선택 후 62.0%  =  **4.4배 농축**
```
그리고 `exp-035` 가 정확히 그 가중을 쓴다 — `n_ok 0~1 → 4배` · `2~4 → 2배` · `5~8 → 1배`.
우리가 잰 지대 밀집 대역(`≤8/32` = `n_ok ≤2`)과 **정렬돼 있다**.

**→ §13 의 「미착수」는 유지되나 근거가 정확해졌다**: *「대리 변수가 좋아서」* 가 아니라
**「그 대리 변수의 농축률이 이미 `exp-035` 에 반영돼 있어서」** 다.

### 13-6. `exp-035` 는 「어려운 것 전부」가 아니다 — 실재하는 빈칸 (2026-08-27)

### 13-7. 「넓고 어려운」 풀은 미측정이다

`exp-024`(넓은 풀)는 실패했으나 **진단이 «넓어서»가 아니라 «쉬워서»** 였다 —


**추가 위험**: `exp-035` 의 가치는 「같은 체제 · 다른 데이터」의 **충돌률 56.2%** 라는

**풀을 넓히면 그 위치가 움직인다** — 좋아질지 나빠질지 모른다.

**→ 대회 이후 최우선 후속 과제로 기록한다.** SFT 축 0승 10패에서 **처음으로 구체적인
미측정 셀**이며, 폐쇄 근거가 «축이 죽었다» 가 아니라 «그 조합을 안 해봤다» 인 유일한 자리다.

### 13-9. 프레이밍 정정 — **주제가 아니라 난이도로 말한다** (`src/eval/difficulty_framing.py`)

§12-1 을 «경시형 +1.30 / 그 외 −0.40» 으로 적었더니 *「train 을 주제별로 뜯어봤다」* 로
읽힐 소지가 있다는 지적을 받았다. **설계는 애초에 주제가 아니라 해결률로 골랐으므로**
(`build_contest_pool.py` + 해결률 역비례 채택) 진단도 난이도로 하는 것이 정합한다.

⚠ 회귀-평균을 막기 위해 **난이도는 v2 의 다른 시드(s342)로 정의**하고 비교는 s42/s142/s242 에서 했다.

| 난이도 (v2 s342 해결률) | 문항 | STAR% | STAR-OLY% | Δ |
|---|---|---|---|---|
| **어려움 (≤8/32)** | 85 | 11.37 | 14.90 | **+3.53%p** |
| 중간 (≤24/32) | 76 | 87.28 | 83.77 | **−3.51%p** |
| 쉬움 (>24/32) | 299 | 100.00 | 100.00 | 0.00 |

**두 프레이밍 대조 (같은 데이터)**
```text
주제 (경시형)      128문항   Δ **+1.30%p**
난이도 (≤8/32)     85문항   Δ **+3.53%p**   ← 2.7배 큰 효과 · 더 좁은 집합
```
**난이도 프레이밍이 더 안전할 뿐 아니라 더 강하다.**

**그리고 「쉬운 문제를 희생한다」는 부정확하다** — 쉬운 문항은 둘 다 100% 로 불변이고,
비용은 **중간 난이도**에서 난다.

**3단계 지대의 난이도 구성**
```text
어려움  전체  85 → 지대 52 (62.0%)   지대의 **81%**
중간    전체  76 → 지대 12 (15.8%)   지대의  19%
쉬움    전체 299 → 지대  0 ( 0.0%)   지대의   0%   ← val 전체는 65%
```
지대에 「쉬움」이 하나도 없어 **−3.51 의 비용은 19% 에만 걸리고 +3.53 의 이득이 81% 에 걸린다.**
**주제를 한 번도 언급하지 않고 전체 기제가 설명된다.**

> **결론은 난이도로 진술한다.** 선별 기준이 실제로 난이도(해결률)였고, 측정된 효과도
> 난이도 쪽이 2.7배 크다. 주제 분석(§12-1)은 같은 현상의 **덜 정확한 대리 관측**이므로
> 진단 기록으로만 남긴다. 배포 분기가 주제를 입력으로 받지 않는다는 점은 §12-1 에 있다.

### 13-10. 순서의 근거 — 「길이 사다리」가 아닌 이유 (예상 질문)

사용자 지적: *「상식적으로는 `STAR → STAR-OLY → LONGCOT` 이 예뻐 보인다 — 길이가 점점 길어지니까」*.
직관적이라 **먼저 반박하지 않으면 청중이 계속 그 생각을 한다.**

```text
STAR → LONGCOT → STAR-OLY  (현행)   385.00    1,152 → 6,106 → 1,175
STAR → STAR-OLY → LONGCOT           382.67    1,152 → 1,175 → 6,106   **-2.33**
```
(3시드 평균 · `docs/why-cascade-works-2026-08-26.md` §7-1)

**순서는 「모델이 얼마나 애쓰나」가 아니라 「관문이 무슨 질문을 하나」로 정해진다.**

| 관문 | 질문 | 필요한 것 | 배치 | 근거 |
|---|---|---|---|---|
| 1 → 2 | 「이 답이 맞나?」 | **다른 시각** | `LONGCOT` | 오답 충돌률 **24.7%** (대조군 66.7%) |
| 2 → 3 | 「64표가 갈렸다, 누가 맞나?」 | **더 나은 실력** | `STAR-OLY` | 어려운 문항 **+3.53%p** |

**「예쁜」 순서는 이 둘을 서로 바꿔 놓아 양쪽에서 진다.**
```text
STAR-OLY 를 2단계로   충돌률 **57.7%** = 대조군(66.7%)과 사실상 같다 (시각이 안 다르다)
                     + 중간 난이도 -3.51%p 비용을 **전 문항의 59.5%** 에 치른다
LONGCOT 을 3단계로    접전에서 문샷 표 증량 = **-2.00**
                     지대는 gold 점유 0.188 vs 최다 오답 0.243 —
                     **같은 분포에서 표만 늘리면 틀린 쪽으로 더 확실히 수렴한다**
```

> **발표 문장**: 캐스케이드는 「모델이 점점 더 애쓰는」 사다리가 아니라
> **「우리가 점점 더 의심하는」 사다리**다. 의심의 단계마다 필요한 것이 다르다 —
> 처음엔 **다른 시각**, 나중엔 **더 나은 실력**.

**예상 질문**: *「싼 전문가(1,175자)를 먼저 쓰고 비싼 모델(6,106자)을 나중에 쓰면 비용상 낫지 않나?」*
→ **2단계 시점에는 어느 문항이 어려운지 아직 모른다.** 전문가를 거기 놓으면 그 대가
(중간 난이도 −3.51%p)를 **전 문항의 59.5% 에** 치른다. 어려운 문항이 걸러진 **뒤에** 써야
이득이 81% 에 걸리고 비용이 19% 에만 걸린다.

## 14. `exp-122` — 어닐링 축도 닫혔다, 주장 강화 (2026-08-28)

§3 에서 *「분산은 학습 체제의 독립 성질」* 이라고 했으나, 근거였던 epoch 비교가
**LR 스케줄 교락**이었다(ep1.38 은 중간 체크포인트라 LR 이 피크의 23.2%).
`--epochs 1` 로 새로 학습해 **완전 어닐링(LR 0)** 판본을 만들었다.

```text
                        n_eff   고유답   maj@32
exp-122 (ep1 어닐링)     **5.20**   9.47   73.70%   ← 셋 중 가장 흩어진다
LITECOT ep2                5.12   9.29   75.00%
LITECOT ep1.38             5.03   9.17   75.00%
```

**어닐링이 분산을 줄이기는커녕 늘렸다.** 사전 등록 문턱(≤4.00)에 한참 못 미친다.

```text
학습량 축   69% → 100% 학습        n_eff 5.03 → 5.12   (31% 차이에 0.09)
어닐링 축   LR 23.2% 잔존 → LR 0    n_eff 5.03 → 5.20   (**반대 방향**)
```
**두 손잡이를 다 돌렸는데 `n_eff` 가 5.0~5.2 를 벗어나지 않는다.**
§3 의 결론이 교락 없이 성립한다.
