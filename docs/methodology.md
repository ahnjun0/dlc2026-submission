## 1. 한 문단 요약

`Qwen2.5-3B-Instruct` 를 자기증류(STaR) SFT 로 다듬은 **주 모델**과 long-CoT 로 full FT 한
**파트너**를 만들고, 두 모델의 표를 합쳐 다수결한다. 리더보드 **0.80024 (665/831)** — 두 생성 배치에서 재현.

**그러나 이 프로젝트의 실질적 결론은 성능 기법이 아니라 다음 관측이다.**

> **학습은 이 모델의 능력을 바꾸지 못했다. 바꾼 것은 회수율이며, 그마저도 작다.**
> 무학습 베이스 모델의 `pass@32` 는 **91.30%** 이고, 우리가 만든 10개 학습 체제는
> 전부 **90.65 ~ 92.61%** 안에 있다. 대신 **모델 다양성**이 합집합 커버리지를
> **95.65%** 였다. ⚠ **2026-08-25 철회** — 이는 `10모델 × 32표 = 320표` 이고 개별 32표와 비교한 **표 수 교락**이었다. 같은 표 수로 재면 `pass@k` 는 **시드 다양화가 오히려 낫다**(96표 94.35 vs 93.26). `maj EM` 에서는 모델 다양화가 낫되 128표에서 이점이 사라진다.

우리 점수의 유일한 실증된 이득(LB `+3문항`, 1위 탈환)은 **집계**에서 나왔다.

## 2. 문제의 구조 — 두 가지 실패를 분리했다

`pass@32`(32샘플 중 한 번이라도 정답)와 `maj@32`(최빈값이 정답)를 분리해 보면
병목이 어디인지 즉시 드러난다.

```
① 뚫기  pass@32 ≈ 91%     →  9% 는 32번 시도해도 못 닿는다
② 맞추기 maj@32  ≈ 82%     →  **9%p 가 "닿았는데 못 고르는" 손실**
```

두 달 동안 시도한 학습 기법 대부분은 ①을 겨냥했고, ①은 **베이스 모델에서 이미 포화**해 있었다.
실제 손실은 ②에 있으며 이는 **집계·선택의 문제**다.

### 오답의 성격 (전수 분류 125건 + 원문 판독)

```
CONCEPT 30% · SETUP 18% · ARITH 8%
오답의 **59% 가 체계적**  (±1 경계 11 · 배수 10 · 부호 1)
정답 풀이와 다수 오답 풀이의 **공통 시작 5%** — 접근부터 갈린다
```

→ "계산 분산"이 아니라 **"해석 다수결 패배"**다. 처방은 표 증량이 아니라
**해석 분포가 다른 파트너**다. 이 진단이 파트너 전략의 근거다.

## 3. 핵심 발견 — 파트너 가치는 강함이 아니라 **다름**

네 건의 독립 실측이 같은 방향을 가리킨다.

```
① mix 는 문샷보다 **단독이 강한데**(82.61 vs 78.04) **파트너로는 약하다**(+1.10 vs +1.27)
② 문샷의 풀이 경로 합의도는 **0.05** — v2(0.22)·mix(0.21)와 차원이 다르다
③ 같은 문샷을 16k 로 **더 잘하게** 만들자 파트너 가치가 떨어졌다 (+4.75 → +2.60%p)
④ 문샷 max_tokens 2048→8192 는 **단독 +4.13%p 인데 풀링 ±0.00** (379문항 중 34개 승패 상쇄)
```

> **파트너는 φ(오류상관)로 고르고 단독 점수로 고르지 말 것.**

> ⚠ **2026-08-25 보강**: φ 는 *오류 여부* 상관만 잰다. 앙상블에 실제로 필요한 것은
> **둘 다 틀렸을 때 같은 정수를 내는가**(오답값 충돌률)이며 φ 로는 안 잡힌다.
> 실측: v2 ↔ v2 자기 다른 시드 **59.0%** 가 기준선인데 경시STaR 57.7 · NEFTune 60.0 ·
> KTO 64.9 로 전부 그 수준이고, **문샷만 23~30%** 다. φ 로는 연속선으로 보이던 것이
> 이 지표로는 이산적이다. **다만 φ 를 대체하는 게 아니라 함께 써야 한다** —
> 충돌률만 보면 약하고 산만한 모델도 다양해 보인다. 최소 세 전이를 같이 봐야 한다:
> ① v2 오답일 때 파트너가 정답인 비율 ② 둘 다 오답일 때 충돌률
> ③ v2 정답일 때 파트너가 파괴하는 비율
> 실측 상관: φ↔기여 `r = −0.879` vs 단독성능↔기여 `r = −0.774`.

**파트너 가치의 물리학**: 파트너가 잘 마무리할수록 표가 **틀린 답 하나로 뭉쳐** 주 모델의
정답을 누른다. 잘릴 땐 표가 흩어져 무해하다. 그래서 **파트너 개선 시도는 전부 역효과**였다.

**모델 2개가 최적**이다. 3자 96표는 81.2~81.7%, 6자 192표는 81.2% — 약한 모델의 표가 희석한다.

## 4. 판정 방법론 — 이 프로젝트의 실질적 산출물

3B 모델에서 유의미한 개선은 **1%p 미만**이고, 그 규모에서는 **판정 설계가 곧 결과**다.
아래는 전부 **잘못 판정한 사례를 겪은 뒤** 만든 규칙이다.

### 4.1 기준선은 최고값이 아니라 **기대값**

챔피언 점수로 쓰던 `83.04%` 는 4시드 중 **최고값**이었다(실제 평균 82.17, 폭 1.96%p).
D-Day 는 시드를 한 번 뽑으므로 기준선은 기대값이어야 한다.
**이 오류로 실제로 이기는 카드(문샷 파트너)를 P=92% 로 오판해 보류했다** (정정 후 98.8%).

### 4.2 채택 게이트

```
문항 부트스트랩 **P(이득) ≥ 95%**
최소 2시드 · 기준선은 4시드 기대값 · **시드 간격 100 이상**
```

시드 간격이 중요하다 — vLLM 은 자식 시드를 `seed..seed+n-1` 로 만들어 `n=32` 에서
**s42 와 s44 는 30/32 가 겹친다**. 과거 "2시드 통과" 판정들은 분산을 과소평가했을 수 있다.

### 4.3 새 판정법은 **역예측으로 검증**한다

이미 결과를 아는 실패 사례를 넣어 기각되는지 먼저 확인한다.
풀링 시뮬레이터는 LB 에서 −4문항이었던 `sub-005` 파트너를 **P=70.8% 로 정확히 기각**했다.

### 4.4 대조군 세 관문 (2026-08-17 완성)

```
① 라우터는 **gold 없이** 계산 가능해야 한다        (관측 가능성)
② 대조군은 **표 수를 맞춰야** 한다                 (exp-055 교훈)
③ **주 모델 시드를 바꿔 복제해야 한다**             (신설)
```

**③은 하루에 네 번 작동했다.** 단독 A구역 · 3자 풀링 · 접전 라우팅 · d2 주 모델 —
모두 한 시드에서 통과했다가 시드 복제에서 사라졌다. **③이 없었다면 넷 다 잘못 채택했을 것이다.**

②만으로는 부족하다: `v2+문샷+d2` 는 표 수를 맞춘 대조군을 `P=93.4%` 로 통과했으나
주 모델 시드를 바꾸자 `−2/−1/0` 이 되어 평균 `+0.25문항` 으로 무너졌다.

### 4.5 층화의 함정

**baseline 관측값으로 구간을 나누면 회귀-평균이 개선처럼 보인다.**
"v2 가 0표인 문항"만 모으면 비교 모델은 내려갈 수 없고 올라갈 수만 있다.
층화 없는 전체 행을 쓰거나 **교차 적합**(블록 A로 구간 정의 → 블록 B에서 측정)할 것.

같은 이유로 **문항 단위 폴드를 교차하지 않은 누설**이 AUC 를 0.62 → **0.94** 로 부풀렸다.

### 4.6 결정성

`VLLM_BATCH_INVARIANT=1` 로 실행 간 잡음이 0 이 된다. **단 청크가 다르면 여전히 갈리므로**
(일치율 99.22%) A/B 는 청크까지 고정한다. 결정성 없이는 1%p 미만 판정이 전부 무의미하다.

### 4.7 AUC 를 채택 근거로 쓰지 않는다

쌍별 우세와 누적 질량은 다른 목적함수다. 가중·필터 카드는 **필요 배율 `r` vs 실제 배율 `R`**
로 판정한다 (exp-066: 전체 AUC 0.62 인데 접전 문항은 0.5338).
판별 AUC 가 높은 특징이 앙상블 가중으로는 해로울 수 있다 — 답 특징 7개는 AUC 0.85 인데
Δ −1.00 이었다(*"문항의 최빈 답에 가까운 답이 정답"* 을 학습할 뿐 = **다수결의 재진술**).

### 4.8 짝 대조군은 **같은 생성 배치**로 만든다 (2026-08-22 신설)

`exp-089` 에서 후보만 제출했다면 소실된 `sub-008`(0.80385, 게다가 3자 구성)과 비교해
**−5문항으로 과대평가**했을 것이다. 같은 배치로 기준선을 재고정(`sub-010` 0.80024)하니
실제 차이는 **−2문항**이었고, 두 제출물은 **51/831 에서만 달랐다**.
> 비교 대상이 사라졌으면 **다시 만들어서 비교한다.** 기억 속 숫자와 비교하지 않는다.

### 4.9 하이퍼파라미터의 근거를 못 대면 **아직 설계되지 않은 실험**이다 (2026-08-22 신설)

`exp-091` 은 `N=48·T=1.3` 을 어림으로 정했다. 근거를 요구받아 실측하니 **전제가 무너졌다** —
분기점은 7토큰이고, 접두는 이미 28/32 고유이며, **접두 다양성과 답 다양성은 무상관(r=0.105)** 이었다.
> 착수 전에 "이 값이 왜 이 값인가" 를 **데이터로** 답할 수 없으면 돌리지 않는다.

### 4.10 프록시 정제를 멈출 지점을 정해둔다 (2026-08-22 신설)

`exp-091b` 에서 '수치군' 지표가 세 번 침식됐다(표면→의미→서식 잡음 71.6%). 그동안
실측 비용은 **25분**이었다.
> **프록시 개선 비용 > 실측 비용이면 즉시 실측으로 간다.**

### 4.11 공통 성분은 복제하지 않아도 된다 (2026-08-22 신설)

`문샷 + X` 에서 X 만 바꾸는 비교는 문샷이 **짝 차분에서 상쇄**된다. 문샷을 s42 로 고정하니
4시드 판정이 시드당 3.5시간 절약되어 **50분**에 끝났다(`exp-090`).

### 4.12 스윕에는 **셔플 귀무 대조군**을 붙인다 (2026-08-22 신설)

표차 조건부 엔트로피 가중을 25점 격자로 스윕해 **최고 +1문항**을 얻었다. 그런데
**엔트로피를 문항 내에서 셔플하고 같은 격자를 200회 돌리니 최고값 중앙이 +1** 이었다
(90분위 +2 · p = 0.580).

```
val460 에서 25점 격자 best-of-sweep 의 **잡음 바닥 = +1문항** (90분위 +2)
```

> **점 추정 +1~2 는 귀무로 간주한다.** 스윕의 최고값은 반드시 같은 격자의
> 셔플 대조군과 비교한다. 이 자가 없으면 잡음을 발견으로 읽는다.

### 4.13 **사후에 정의한 대상의 Δ 를 증거로 쓰지 않는다** (2026-08-25 신설)

4.5(층화의 함정)는 *문항* 선택에 대한 규칙이었다. 같은 오류가 **추적 대상 선택**에서 재발했다.

```
같은 데이터 · "선두 오답 Δ" 를 정의만 바꿔 재측정 (Step-DPO d2)
  ① v2(개입 전) 기준 사전 고정   **−0.61표**   ← 편향 없음
  ② 두 분포 합산 기준             +0.46표      ← 기록돼 있던 값
  ③ d2(개입 후) 기준              +1.69표      ← 오른 답을 고르는 정의. 순환
```
**부호가 뒤집힌다.** 2026-08-17 에 기록했던 *"확신 강화가 지는 쪽을 더 세게 만든다"* 는
③에 가까운 정의에서 나온 결론이었고, 사전 고정하면 성립하지 않는다.

**그리고 대조군은 0 이 아니라 "아무것도 안 바꾼 재실행"이어야 한다.**
```
같은 84문항 · 선두 오답 사전 고정        gold Δ    선두오답 Δ
v2 자기 시드 s142                       +0.23      −0.95
v2 자기 시드 s242                       +0.48      −1.50
Step-DPO d2                            +0.26      −0.61
```
**학습한 모델이 재뽑기보다 적게 움직인다.** gold 상승은 전부 회귀-평균이다.

### 4.14 선호·RL 은 **SFT 체크포인트에서 출발**한다 — 스크립트마다 확인 (2026-08-25 신설)

`exp-100`(KTO)이 **베이스 모델에서 학습**돼 *"v2 를 개선했는가"* 가 아니라
*"베이스+KTO 1epoch vs 베이스+STaR SFT 2epoch"* 를 비교하고 있었다. 전수 감사 결과
DPO 4건·GRPO 는 전부 `--model <병합 SFT>` 로 정상이었고 **KTO 하나만 예외**였다 —
새로 쓴 스크립트가 기존 패턴을 물려받지 못한 것이다.
→ **재실행(`exp-105`)에서 `pass@1` 이 71.94 → 73.67 로 올라 v2(73.26)를 넘었다.**
축의 결론은 같았으나, **틀린 실험으로 축을 닫아둔 상태였다.**

### 4.15 새 실험 헤더를 쓰기 전에 **세 문서를 grep 한다** (2026-08-25 신설)

`exp-104`(접전 지대 16k)를 착수하고 GPU 25분을 쓴 뒤에야 그것이 **이미 닫힌 축**임을 알았다.

## 4-B. **기저율 82% — 폐쇄된 축 대부분의 단일 설명** (2026-08-25)

두 달간 닫은 축들의 공통 원인을 하나로 좁혔다.

**실측 (exp-100 · val460 · 추적 대상 사전 고정)**
```
구간            문항     Δgold    Δv2선두    KTO/재뽑기 배율
v2 승           376     −0.65     −0.65      **3.6배**
v2 패            84     +0.57     −0.33      **2.5배**
```
v2 를 **그냥 다시 뽑아도 부호가 같다**(회귀-평균). 학습이 바꾼 것은 **방향이 아니라 크기**다.
정답 정보는 전혀 들어가지 않았다 — 오히려 이득 배율(2.5)이 손실 배율(3.6)보다 **작다**.

```
v2 가 이미 맞는 문항   376 (**82%**)   ← 건드리면 잃을 것만 있다
v2 가 틀리는 문항       84 (18%)
gold 표 총합   376×(−0.65) + 84×(+0.57) = **−196표**
```

> ⚠ **2026-08-25 외부 검토로 정정.** 종전 문장 *"82:18 판에서 **반드시** 진다"* 는 **거짓**이다.
> 정확한 형태는 **교환비 장벽**이다. 기존 정확도 π, 오답 구출 조건부확률 r, 정답 파괴 조건부확률 b 일 때
> ```text
> ΔAcc = (1−π)·r − π·b   →   이기려면  r/b > π/(1−π) = 376/84 = **4.48**
> ```
> 즉 **불가능 정리가 아니라 매우 높은 장벽**이다. `exp-100` 은 비율이 **0.88** 로 장벽의 20%에
> 그쳐 확실히 졌지만, 이것으로 *모든* 전역 개입이 진다고 일반화할 수는 없다.
>
> **그리고 gold 표 총합(−196표)은 평가값이 아니다.** 평가는 **최빈답 Exact Match** 이므로,
> 이미 안전하게 맞는 문항에서 잉여 표를 잃고 접전 오답 하나를 뒤집으면
> **표 총합은 내려가도 정확도는 오를 수 있다.** 위 −196표는 기제의 방향을 보여줄 뿐
> 정확도 변화의 증명이 아니다.
>
> 발표·문서에서 쓸 정확한 문장:
> *"82%가 이미 맞기 때문에 비표적 개입에는 약 **4.48:1** 의 구출-파괴 교환비가 요구된다.
> 우리가 측정한 전역 개입들은 이 장벽을 넘지 못했고, KTO 는 0.88 에 그쳤다."*

**표적성은 학습 문항에 남고 부작용만 새 문항으로 전이된다** — 새 문항에서 모델은 어느 궤적이
오답인지 모른다. 전례: `exp-036` 표적 **+11.11%p** 인데 전체 **−0.65%p**.

**→ 개입은 조건부여야 한다.** 유일하게 이긴 카드(`exp-101` 3단계)가 그 형태다 —
접전 지대의 기저율은 **23%**(16/69)라 위로 갈 여지가 있다.
**닫힌 축 상당수는 기법이 나빠서가 아니라 게이트가 없어서 죽었다.**

> ⚠ 단, **조건부라고 다 되는 것은 아니다.** 전역에서 진 `exp-100` 을 지대에 넣어도
> 3번째로 +0, 4번째로 −3 이었다. 그리고 69문항 지대는 **±3 이 잡음**이라
> val 로는 조건부 재판정을 할 수 없다 — LB 짝 검정이 유일한 판정 수단이다.

> 기준선은 v2 자기 4시드 폭 **1.96%p** 이며, **단일 시드 |Δ|<2%p 로 닫은 축은 판정력이 없었다**

### 5.3 선호학습(DPO) 계열 0승 4패 — **단일 구조적 원인**

`arXiv:2410.08847`(likelihood displacement)의 CHES 를 우리 쌍에 직접 계산했다.

```
                  CHES 평균   p10      표준편차   셔플 대조
Step-DPO(079)      **0.976**  0.946    **0.030**   0.007
±1 DPO(073)          0.852    0.692      0.166    −0.021
DPO1(032)            0.880    0.716      0.133     0.042
```

**같은 문제에서 만든 쌍은 구조적으로 CHES 가 높다.** 그리고 CHES 가 높을수록 DPO 는
**선호 응답의 확률을 떨어뜨린다**(`arXiv:2402.13228` 은 같은 현상을 "편집 거리가 작은
쌍에서 특히 심하다"로 표현). Step-DPO 는 같은 prefix 를 공유하고 한 단계만 다르므로
**교과서적 최악 조건**이며, 실제로 CHES 순서가 붕괴 순서와 일치했다.

수학 문제의 선호 쌍은 **정의상 같은 문제에서 나와야** 하므로 이 함정은 회피 불가능하다.
`p10 = 0.946` 이라 **CHES 필터도 쓸 수 없다** — 걸러낼 꼬리가 없고 분포 전체가 꼬리다.

### 5.4 DPO 의 세 손잡이를 모두 돌린 결과

```
속도(lr)      d1 → d2      +1~2문항, 무효
용량(epochs)  d2 → d4      **−11문항, 붕괴**
앵커(β)       0.1→0.3→0.5  손상 **10.7배 감소** · **pass@32 92.61% (최고 기록)**
                           그런데 **maj@32 +1문항**
```

**마지막 손잡이는 실제로 작동해 능력을 올렸다. 그런데 점수가 안 올랐다.**
새로 커버된 11문항의 gold 득표는 **중앙값 1표 / 32** 였고 **다수결 승리는 0개**였다.

> **병목은 학습이 아니라 수확이다.**

### 5.5 왜 엔트로피 붕괴가 치명적인가 — 원문 판독

`d4`(β=0.1, 4에폭)는 `pass@32` 가 **오르는데** `maj@32` 가 2.39%p 무너졌다. 오답을 읽었다.

```
v2:  10 + 5 + 7 + 6 = **28**   ✓
d4:  10 + 5 + 7 + 6 = **38**   ✗   ← 추론 구조는 문장 단위로 거의 동일
```

그리고 **32/32 전부 같은 실수**를 한다. 별도 산술 프로브(400문항 순수 계산)에서 **d4 는
5개 모델 중 1위(98.0%)** 였다 — **덧셈을 못 하는 게 아니다.**

> **다수결은 실수가 무작위라서 작동한다. 엔트로피 붕괴는 실수를 결정론적으로 만들어
> 다수결의 작동 원리 자체를 제거한다.**

## 4-C. **결론 문구의 범위** — 무엇을 주장해도 되는가 (2026-08-25 · 외부 검토 확정)

성능 축이 소진됐을 때 *"천장"* 을 선언하고 싶어진다. **그 문장의 범위를 좁히지 않으면
방어할 수 없다.** 외부 검토로 확정한 표현은 다음이다.

> **현재 구축해 시험한 세 생성 체제와 배포 예산에서, 정수 빈도·모델별 지지 위상으로 관측되는
> 신호는 현행 캐스케이드 이상의 EM 으로 안정적으로 전환되지 않았다. 1위가 틀렸다는 정보는
> 존재하지만, 올바른 대안을 식별하는 배포 가능한 신호는 검출되지 않았다. 따라서 이
> 관측·행동 클래스에서는 실용적 포화에 도달한 것으로 판단한다.**

**쓰면 안 되는 표현과 이유**
```
"모델의 절대적 천장"          우리는 3B 의 한계를 측정한 적이 없다
"허용된 생성 채널의 천장"      규칙이 허용하는 **모든** fine-tuned 3B·프롬프트·다단 정책을
                            시험한 것이 아니다 → "**현재 구축해 시험한** 생성 채널"로 한정
"정보이론적 천장"             관측 절차의 한계이지 정보의 한계가 아니다
"판별 정보가 없다"            **1위 오답 감지는 된다**(접전 AUC 0.63~0.79).
                            안 되는 것은 **올바른 대안의 식별**이다 — 두 타깃을 구분할 것
```

### 4-C-1. 포화를 주장하기 전에 정해야 할 것 — **실용 최소효과**

*"유의하지 않다"* 로는 포화를 주장할 수 없다. **먼저 최소 가치 효과를 정하고**,
그 아래임을 **검출력과 함께** 보여야 한다.

```
실용 최소효과(MDE)   **+3문항 / 460 = +0.65%p**
포화 주장 조건        ① 선택 절차 전체를 포함한 **단측 95% 상한이 MDE 아래**
                    ② 동일 파이프라인이 **+3문항 주입을 80~90% 이상 검출**
```
②가 없으면 *"못 찾았다"* 와 *"찾을 능력이 없다"* 를 구분할 수 없다.
검출력은 **반합성 positive control** 로 잰다 — 실제 vote tensor 에 알려진 크기(+1/+2/+3/+5문항)의
구출 효과를 주입하고 판정 파이프라인의 검출률을 측정한다.

### 4-C-2. 실패 실험을 천장 증거로 쓰려면 **양성대조가 필요하다**

한 설정이 실패했다고 넓은 결론을 내리면 안 된다. 예: 후보 비제약 합성(B2)이 실패했을 때
그것이 *"재조합할 정보가 없다"* 의 증거가 되려면 **두 대조**가 필요하다.

```
① 합성기 민감도 양성대조   정답 풀이 하나를 조각내고 **최종 정수를 제거**한 뒤 오답 풀이들과
                        섞어 넣는다 → 합성기가 정답을 **복원하는가**
                        (복원 못 하면 "정보가 없다"가 아니라 "합성기가 못 한다")
② 동일 비용 fresh-solve   풀이 묶음 없이 문제만 다시 푼 표와 **같은 토큰 예산**으로 비교
                        → 합성이 단순 추가 샘플보다 나은가
```
> **반합성 vote-tensor 주입(4-C-1②)은 평가 파이프라인의 검출력만 확인한다.**
> 합성기가 실제로 재조합할 수 있는지는 ①로 따로 확인해야 한다. 둘은 다른 대조다.

## §5 분산이 지배 변수다 — 「능력↑ 점수↔」의 정량적 답 (2026-08-27 추가)

두 달간 열다섯 번 만난 «능력은 올랐는데 점수가 안 온다» 를 상관으로 표현할 수 있게 됐다.
`exp-120`(중간 길이 full FT)이 제3의 체제(`n_eff` 5.12)를 만들어 **분산 축이 넓어진** 덕이다.

**능력이 비슷한 7개 모델**(`pass@32` 90.87~92.61%)에서:
```text
pass@32 ↔ maj@32   r = **+0.134**   ← 능력은 점수를 거의 예측 못 한다
n_eff   ↔ maj@32   r = **−0.920**   ← 분산이 점수를 결정한다
```
**우리가 두 달간 최적화한 것은 전자이고, 배포 점수를 지배한 것은 후자였다.**

**길이는 원인이 아니다.** 7개만 보면 `길이 ↔ n_eff = +0.912` 로 길이가 원인처럼 보이지만,
`exp-120`(1,976자에 `n_eff` 5.12)을 넣으면 **+0.185 로 무너진다**. 문샷은 3배 긴데 3.59 다.
→ 분산은 **길이의 부산물이 아니라 학습 체제의 독립 성질**이다.

**함의**
```text
① 설계 목표    «더 잘 푸는 모델»(pass@32)이 아니라
              **«같은 능력에서 덜 흩어지는 모델»**(n_eff)이 maj@k 배포의 목표다
② 최적점 없음  n_eff 2.70~5.12 구간에서 **단조 악화**다. «적당한 다양성» 을 추구할 이유가 없다.
              다양성은 **모델 간**(오답 비상관)에서 얻고 **모델 내**(표 분산)에서는 줄인다
③ 파트너 조건  문샷이 좋은 파트너인 이유는 길어서가 아니라 **v2 와 다른 곳에서 틀리면서
              (충돌률 24.7%) 자체 분산은 3.59 로 억제**돼 있기 때문이다.
              exp-120 은 충돌률 13.8% 로 더 다른데 **자체 분산 5.12** 라 못 쓴다
④ 집계로는 못 고친다  소수 답 가지치기로 n_eff 를 4.08 → 2.00 으로 줄여도 **정확히 0문항** 변화
```

**한계**: n=7~9 로 작다 · `n_eff ↔ gold표 −0.987` 은 부분적으로 산술이다 ·
한 시드·한 평가셋(val460, 낙관 편향 확인) · `exp-120` 은 극단점이라 지렛대가 크다.
